# N002 image-space claim audit

Audited the supplied note at SHA-256 `20589ecb5bd3892a4671143a9159ca190b701fc62850dcd87a8e545276c870a6` against the pinned Skyrim SE 1.7.104 shader package, existing native image-space traces, the current record decoder, and the scoped Mudcrab shaders. This audit covers IMGS, IMAD, WTHR, CLMT, adaptation, bloom, and color grading only. Static shader evidence establishes equations for the identified package programs; it does not establish that a program ran in a particular retail frame.

The clearest record-layout correction is modern `IMGS`: `HNAM` has nine values in the recovered order of eye-adapt speed, bloom radius, bloom threshold, bloom scale, receive-bloom threshold, white, sunlight scale, sky scale, and eye-adapt strength. `CNAM` separately holds saturation, brightness, and contrast; `TNAM` holds tint amount and RGB. The supplied minimum/maximum and target exposure members do not occur in that modern layout. The older `ENAM` block is a separate legacy layout.

The supplied geometric-log-mean adaptation model does not match the shipped shader. The mapped package reduces weighted samples arithmetically using `(0.2125, 0.7154, 0.0721)`. Its later history update has two channels with separate rates, moves by `sign(delta * rate) * min(abs(delta), max(abs(delta * rate), 1/256))`, keeps prior XY when the accumulated input is NaN, and writes current luminance to Z. Depending on history state and configuration, the native graph can replace the final ordinary reduction and can stop at 2×2; a universal 1×1 endpoint is unsupported. The tone program forms its exposure term from scene luminance times `A.y/A.x`; there is no recovered target/min/max exposure clamp.

The supplied bloom model also differs in key operations. Bright-pass threshold is subtracted componentwise from scaled RGB; its alpha comes from adaptation. The HDR parent picks a discrete vertical BrightPassN followed by horizontal BlurN, with pinned odd tap counts and weights. Bloom scale is applied in the bright pass; the tone program then combines scene and bloom with the receive-bloom threshold. The exact active values, domains, and route remain frame-specific.

The grading equations use shader weights `(0.2125, 0.7154, 0.0721)`, not the supplied coefficients. Saturation is followed by tint interpolation toward `Y * tintRGBA`, then brightness and contrast operations whose pivot is sampled adaptation X. These operations also affect alpha before RGB saturation and final transfer. The simplified 0.5-pivot contrast and final RGB multiplication tint are contradicted by the scoped equations.

IMAD native evidence supports ordered per-modifier scalar updates and amount-weighted tint/fade aggregation, plus a modifier-list walk. The active records, curve behavior, strength/duration lifecycle, full crossfade path, and composition with the base record remain open. WTHR stores four named color keys (Sunrise, Day, Sunset, Night) per NAM0 color group and four IMSP links. Those four keys do not establish eight distinct authored stages or the supplied intermediate transitions. WTHR supplies sunlight color keys here, while its direction is not represented as a WTHR vector; native sun trajectory and selected state remain separate connections. CLMT exposes timing bytes and weather choices, but the stated lunar-cycle and seasonal behavior is not closed by this evidence.
