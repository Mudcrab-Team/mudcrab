The supplied model is wrong on several specific operations. The mapped luminance weights are `(0.2125, 0.7154, 0.0721)`. The reduction is arithmetic. The ordinary native graph may replace the final reduction and can write 2×2 history, so “always reduce to 1×1” is false.

The HDR parent uses componentwise bright-pass thresholding and a selected vertical bright-pass blur followed by horizontal blur with 3–15 taps. The tone program adds bloom with `saturate(ReceiveBloomThreshold - mappedLuminance)`. It then applies saturation, a blend toward luminance times tint RGBA, brightness and contrast about adaptation X. Those operations affect alpha. RGB is saturated and passed through the shared reciprocal-`fGamma` power; the Fade child blends RGBA afterward. Thus “fGamma last” is valid only inside that shader’s output path, before Fade and later renderer/presentation clients.
