> **Topic:** Ranking of the 14 wave-2 deep dives.

Wave 1 is a coarse source map, not a coverage proof. For example, the animation report has a measured 12 feature rows for about 11,000 lines. Rank combines estimated value to a playable port and estimated coarseness.

1. **Animation graphs and clips — very high value, very coarse.** Scope: `src/anim/graph*`, `generators.cpp`, `state_machine*`, `modifiers.cpp`, `src/importer/convert/hkx_import.cpp`. Question: which node classes, transitions, annotations and representative creature clips work end to end, and which are unsupported? Output: node coverage matrix, conversion-to-player path, missing cases and focused test ideas. Feeds #470, #471 and #512–#515.
2. **Papyrus VM and natives — very high value, coarse.** Scope: `src/script/vm*`, `natives.cpp`, `src/engine/papyrus*`, `*_natives.cpp`, `src/importer/convert/script_import.*`. Question: which instructions, waits, attachments, persistence and native calls actually work, and what returns a default? Output: opcode/native support matrix with provenance and scheduler diagrams. Feeds the inventory's Phase 3 scripting milestone.
3. **Quests, conditions and story events — very high value, coarse.** Scope: `src/game/quests*`, `conditions*`, `story_manager*`, `src/engine/app_dialogue.cpp`. Question: which stage, alias, condition and startup paths are implemented through the host? Output: lifecycle map, unsupported facts and a minimal quest fixture plan. Feeds Phase 3 scripting and Phase 4 gameplay.
4. **Save/load and mutable world state — very high value, coarse.** Scope: `src/engine/app_saves.cpp`, `src/game/game_save.cpp`, quest and script serialization, `docs/formats/ost.md`. Question: which state survives reload and how are plugins and versions checked? Output: section-by-section save coverage and migration/failure test matrix. Feeds Phase 4 gameplay.
5. **UI movie conversion and host — high value, coarse.** Scope: `src/importer/convert/ui_*`, `src/ui/player`, `src/ui/menu*`, `src/engine/app_menus.cpp`. Question: which AS2/GFx and host callbacks are needed for a minimal HUD, dialogue and inventory? Output: runtime boundary, dependency and unsupported-feature matrix, plus a staged implementation proposal. Feeds Phase 3 UI.
6. **Audio ingestion and platform-neutral interface — high value, coarse.** Scope: `src/importer/convert/audio_import.*`, `src/audio/system.*`, `sound.*`, `clip.*`, `music.*`, `ambience.*`. Question: which descriptors, codecs and events are necessary, and what depends on XAudio2? Output: dataflow, codec/license table and portable backend boundary. Feeds #521 and #522.
7. **NPC navigation and packages — high value, coarse.** Scope: `src/game/navmesh.*`, `ai.*`, `detection.*`, `src/engine/app_ai.cpp`, forms navmesh decoding. Question: how do graph links, path queries and package execution connect across spaces? Output: path and unsupported-link matrix with deterministic fixture ideas. Feeds Phase 4 gameplay and builds on #385.
8. **Actor assembly and rendering — high value, coarse.** Scope: `src/importer/convert/actor_import.*`, `src/engine/actors.*`, `app_actors.cpp`, relevant skin materials. Question: how are child and creature rigs, body parts, skin and authored idle assets resolved? Output: dependency graph and representative asset test matrix. Feeds #470, #471 and #512–#515.
9. **Materials, lighting and weather — high value, coarse.** Scope: `shaders/mesh.frag`, `common.glsl`, `src/render/pipelines.*`, `src/engine/weather.*`, `precip_occlusion.*`. Question: which authored data reaches each shader and weather effect, and what is approximated? Output: field-to-shader table and same-pose comparison plan. Feeds #435, #480, #484, #488, #490 and #546.
10. **Grass, far views and water — high value, coarse.** Scope: `src/engine/grass.*`, `src/importer/far/`, `src/render/renderer_water.cpp`, `shaders/water.frag`. Question: which placement, impostor and water techniques can complement Mudcrab's existing derived pipeline? Output: algorithm and data-dependency comparison with visual-risk checklist. Feeds #282, #539, #299, #501 and #545.
11. **Physics and movement — high value, medium coarseness.** Scope: `src/physics/world.cpp`, `character.cpp`, `src/engine/movement.*`, `docs/MOVEMENT.md`. Question: which imported layers and controller choices work, and where are dynamic bodies, triggers and water absent? Output: shape/layer coverage and parity test matrix. Feeds #464, #474–#477, #482, #486 and #544.
12. **Combat, inventory and magic — high value, very coarse.** Scope: `src/game/combat.*`, `items.*`, `inventory.*`, `equip.*`, `magic_target.*`, `src/engine/app_items.cpp`. Question: which data-driven rules and host callbacks form a minimal playable encounter? Output: vertical-slice dependency map and unsupported formula ledger. Feeds Phase 4 gameplay.
13. **Render submission and evidence tools — medium value, medium coarseness.** Scope: `src/render/bindless.*`, `gpu_arena.*`, `renderer.cpp`, `tools/audit/history_audit.py`, `tools/perf/`. Question: which submission and image-history methods transfer to Bevy and Metal without copying Vulkan assumptions? Output: platform-neutral techniques, measurement limits and proposed fixtures. Feeds draft #441 and #533, and receipt work #524.
14. **Format and import contracts — medium value, medium coarseness.** Scope: `src/formats/container.*`, `forms.*`, `src/importer/records/`, `incremental.*`, `docs/formats/`. Question: where do stale documentation and unsupported source variants create compatibility risks? Output: version/reader matrix and provenance checklist. Feeds Phase 1 asset-pipeline hardening.
