## 1. Summary

1. The player controller core did not change. In `character.cpp` only 25 lines were added and 10 removed (comments, the open-doorway test, and a ground-body field). In `movement.cpp` one line changed. So the controller feel found in the earlier audit was already present in `8c990420`. The new commits mostly add door crossing, grab, jointed models, and a zoom key.
2. Spud's controller is a port of Skyrim's own rules, not a generic capsule. The mechanisms that likely make it feel right are listed in section 3.3. The ten most likely feel differences to Mudcrab are in section 3.5. The top three are: steps are continuous ramps (Mudcrab lifts the body in one tick), the first-person eye trails on a spring (Mudcrab eye is rigid), and the view is interpolated between 60 Hz ticks (Mudcrab shows none; unverified).
3. Spud's UI is not native C++ drawing. Menus are Skyrim's own Scaleform movies, converted to `.osu` and run by spud's AS2 player. C++ is the engine side of each menu. The UI code changed only in comments, plus one new zoom key (section 4).
4. The three silent-default problems are not fixed: `broad_phase_dirty` is still dead, the hard-coded character layer mask is still used, and NPC perks are still identity (section 5.2).
5. Four wave-2 claims are now wrong or incomplete: "multi-body dynamic models never simulate", "navmesh links ignore type", "conditions on aliases are unsupported", and "acceleration is a placeholder ramp" (section 5.1). Almost every line number cited for `world.cpp`, `ai.cpp`, `actors.cpp`, `app_items.cpp` and `player.cpp` has moved.
6. Licence is unchanged: MIT. No new licence, no vendored code added (section 6). The last commit rewrote comments to remove game-internal names. The rewrite is partial (section 6).

### 3.3 What makes it feel right (mechanisms, with cites)

1. Steps are continuous. The hull has a cone at the bottom ([`character.cpp:836`](https://github.com/chasmlol/spud/blob/e5f2de4b5a612eef3f2cd15e4a84672e9e0a0f1c/src/physics/character.cpp#L836): point at the bottom, octagon at step height + 0.1). A step contact is turned into a ramp plane ([`character.cpp:631-637`](https://github.com/chasmlol/spud/blob/e5f2de4b5a612eef3f2cd15e4a84672e9e0a0f1c/src/physics/character.cpp#L631-L637)). The simplex solve then carries the feet up the ramp at walking speed. No instant lift. This is the opposite of a teleport lift.
2. Descents stay grounded. A 70-unit downward cast keeps the character in `on_ground` with 4x gravity ([`character.cpp:986-990`](https://github.com/chasmlol/spud/blob/e5f2de4b5a612eef3f2cd15e4a84672e9e0a0f1c/src/physics/character.cpp#L986-L990)). Walking down stairs does not enter a fall state.
3. Velocity follows the ground. Requested speed is projected onto the support plane ([`character.cpp:998-1019`](https://github.com/chasmlol/spud/blob/e5f2de4b5a612eef3f2cd15e4a84672e9e0a0f1c/src/physics/character.cpp#L998-L1019)), so slopes do not change speed or bounce.
4. Third-person input smoothing from the game's own settings. A buffer of the last 0.14 s of input ([`movement.hpp:61`](https://github.com/chasmlol/spud/blob/e5f2de4b5a612eef3f2cd15e4a84672e9e0a0f1c/src/engine/movement.hpp#L61), [`movement.cpp:243-311`](https://github.com/chasmlol/spud/blob/e5f2de4b5a612eef3f2cd15e4a84672e9e0a0f1c/src/engine/movement.cpp#L243-L311)) feeds a ramp with a 0.25 s dampen time ([`player.hpp:61`](https://github.com/chasmlol/spud/blob/e5f2de4b5a612eef3f2cd15e4a84672e9e0a0f1c/src/engine/player.hpp#L61), [`player.cpp:674-679`](https://github.com/chasmlol/spud/blob/e5f2de4b5a612eef3f2cd15e4a84672e9e0a0f1c/src/engine/player.cpp#L674-L679)) and a ramp-down limit of 500 units/s per update ([`movement.hpp:60`](https://github.com/chasmlol/spud/blob/e5f2de4b5a612eef3f2cd15e4a84672e9e0a0f1c/src/engine/movement.hpp#L60), [`player.cpp:670-673`](https://github.com/chasmlol/spud/blob/e5f2de4b5a612eef3f2cd15e4a84672e9e0a0f1c/src/engine/player.cpp#L670-L673)). Large direction changes freeze the direction until the change ends ([`player.cpp:667-669`](https://github.com/chasmlol/spud/blob/e5f2de4b5a612eef3f2cd15e4a84672e9e0a0f1c/src/engine/player.cpp#L667-L669)).
5. First person has no ramp at the controller. The comment says "first person has none, measured" ([`player.hpp:57`](https://github.com/chasmlol/spud/blob/e5f2de4b5a612eef3f2cd15e4a84672e9e0a0f1c/src/engine/player.hpp#L57)). Velocity is the request ([`player.cpp:686-688`](https://github.com/chasmlol/spud/blob/e5f2de4b5a612eef3f2cd15e4a84672e9e0a0f1c/src/engine/player.cpp#L686-L688)). ### 3.4 Mudcrab controller today (read-only, `main` as of 2026-11-12)

- Rapier `KinematicCharacterController`, capsule, `autostep: None`, snap-to-ground 12 units, slope climb 50 and slide 55 degrees (`physics.rs:1653-1675`, `physics.rs:94-97`).
