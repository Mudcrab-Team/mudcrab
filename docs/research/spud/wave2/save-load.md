## Architecture

### Shape

Spud does not use Skyrim's `.ess`. It defines `.ost`: a generic `SPUD` chunk envelope ([`docs/formats/ost.md:1`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/formats/ost.md#L1), [`src/formats/container.hpp:29-45`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/container.hpp#L29-L45)) with kind `SAVE` and **version 3** ([`src/formats/ost.hpp:23-24`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/ost.hpp#L23-L24)). A save holds **no content**. The plugin list names the content; each section is one subsystem's *change layer* keyed by FormID ([`src/formats/ost.hpp:5-7`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/ost.hpp#L5-L7)). This is the central design decision and the reason saves stay small.

```
                  frame N                     frame N+3                background thread
  save trigger ──► begin_save()               update_saves()
  (menu/key/      gather all sections   ──►   take_capture_scaled ──►  ost::write(save)
   autosave/      on the MAIN thread           (320x192 RGBA)           write_file(<name>.tmp)
   script/death)  log gather ms                                            rename(.tmp -> .ost)
                        │                                                 remove(replaced file)
                        ▼
                  PendingSave{save, path, replaces, frames_left=3}
                        │
                        ▼  (load request, next frame start)
                  load_game()  ── reads envelope, checks plugins ──► PendingLoad
                        │
                        ▼  loading screen up (>=1000 ms or backdrop)
                  finish_load()  sections applied in fixed order
```

### Lifecycle

1. A trigger calls `manual_save`, `autosave`, `quick_save`, the script hooks, or the console. Each calls `can_save()` first ([`:101-105`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L101-L105)), except that `autosave` also requires a character id ([`:139`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L139)).
2. `begin_save` fills `Header` and every present section, records the load-order hash, requests a capture, and opens `LoadWaitSpinner`.
3. Three frames later `update_saves` scales the capture into `THMB`, sets `m_last_save`, and starts the async write ([`:371-401`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L371-L401)). The write goes to `<name>.ost.tmp`, then renames; the replaced file is removed only after a successful rename ([`:386-399`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L386-L399)).
4. `finish_save_write` joins the future at the next save, load, or save-list refresh ([`:404-411`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L404-L411), called at [`:223`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L223), [`:456`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L456), [`:649`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L649)). `~App` does not call it ([`app.cpp:252-262`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app.cpp#L252-L262)); shutdown relies on the `std::future` destructor blocking until the background thread ends.
5. `load_game` parses the envelope, runs plugin checks, closes menus, opens the loading screen, and stores `PendingLoad` ([`:648-699`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L648-L699)).
6. `finish_load` applies sections in a fixed order, then starts one settle tick before the screen closes ([`:739-869`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L739-L869), [`app_menus.cpp:862-880`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_menus.cpp#L862-L880)).

### Plugin, version, and load-order checking (as implemented)

- **Version**: exactly one accepted number, `k_version == 3`. Anything else throws `ParseError("unsupported .ost version N")` ([`ost.cpp:67-69`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/ost.cpp#L67-L69)). No migration path, no up-converter, no accepted range.
- **Plugin presence**: only names, case-insensitively, one direction. For each plugin in the save, `save_content_ok` asks whether a plugin of that name is in the current order ([`app_saves.cpp:626-632`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L626-L632)). Extra plugins in the current order are not reported.
- **Plugin hashes**: written per plugin ([`ost.cpp:46-52`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/ost.cpp#L46-L52)) and never read for comparison. `rg -n "load_order|content_hash" src/engine` returns only the two write sites and the hash source ([`app_saves.cpp:246`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L246), [`:419`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L419)).
- **Load-order hash**: fold of all plugin hashes, `order = order*0x9E3779B97F4A7C15 ^ hash` ([`app_saves.cpp:242-246`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L242-L246)), stored in `Header.load_order` and never verified. It is a 64-bit fingerprint, so a reorder with the same hashes changes it, but nothing reads it.
- **Plugin header version and masters**: `PluginEntry` carries HEDR `version`, `form_version` and a MAST span ([`forms.hpp:57-77`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/forms.hpp#L57-L77), [`forms.cpp:93-94`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/forms.cpp#L93-L94)). None of these reach the save.
- **"Modded"**: a boolean derived once from the plugin list: official names (`skyrim.esm`, `update.esm`, `dawnguard.esm`, `hearthfires.esm`, `dragonborn.esm`, any `cc*`) are not modded, anything else is ([`app_saves.cpp:56-70`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L56-L70)). It partitions characters (`character id << 1 | modded`, [`:78`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L78), [`:498`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L498)) and prefixes the location with `[M]` in the list ([`:533`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L533)).
- **Vanilla saves**: not readable at all. `.ess` has no `SPUD` magic, so `Reader` throws "not an spud file (bad magic)" ([`container.cpp:35-37`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/container.cpp#L35-L37)).
- **Obsolete flag**: `SaveDetails::obsolete` exists ([`ui.hpp:223`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/ui/ui.hpp#L223)) and is always false; nothing sets it (`rg -n obsolete src` gives only the declaration, the UI setter, [`menus_saves.cpp:56`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/ui/menus_saves.cpp#L56)). No "made by an older version" state exists.

### Corruption and failure behaviour (as implemented)

- Every read is bounds-checked and throws `ParseError` ([`core/binary.hpp:88-92`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/core/binary.hpp#L88-L92)).
- `ost::read` validates magic, kind ([`container.cpp:35-40`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/container.cpp#L35-L40)), version ([`ost.cpp:67`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/ost.cpp#L67)), header size ([`:72-74`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/ost.cpp#L72-L74)), and requires `HEAD`, `TEXT`, `PLUG`; `THMB` is optional ([`:71-92`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/ost.cpp#L71-L92)).
- `refresh_saves` catches any exception per file and marks it `corrupt` ([`app_saves.cpp:466-475`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L466-L475)); corrupt files are still listed, and sorted among the others.
- `load_game` catches a read failure and shows `sSaveGameCorruptMenuMessage` ([`:651-658`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L651-L658)).
- **Uncaught path**: once the envelope parses, `finish_load` decodes each section with no `try`. A truncated but envelope-valid section throws out of `run_frame` ([`app.cpp:399-401`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app.cpp#L399-L401)). `rg -n "try|catch" src/engine/app_saves.cpp` shows only lines 466, 555, 651 — all before `finish_load`. This is a real robustness gap, not just a theoretical one, because sections are length-prefixed by an attacker-writable or disk-truncated file.
- A missing *section* is not an error: every consumer tests `if (auto r = reader(id))` and falls back ([`:758-864`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L758-L864)). Missing `PVM_` means no scripts and no quests are restored, and `OnPlayerLoadGame` is never sent ([`:846-857`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L846-L857)).
- A failed write keeps the previous file: the temp name is used and the replace happens only after a successful rename ([`:386-399`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L386-L399)). `rename` failure logs a warning and leaves the temp file behind.

### Size and speed

Measured facts in code, not in a benchmark:

- Gather time is logged per save (`"save: gathered in {:.2f} ms"`, [`app_saves.cpp:327`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L327)), and size is logged per save (`"save: {} ({} KiB)"`, [`:395`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L395)). The repository contains no recorded run with those lines.
- Envelope overhead is 16 B file header + 16 B per chunk, payload padded to 16 B ([`container.cpp:22-32`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/container.cpp#L22-L32)).
- Fixed costs: `HEAD` 64 B; `PLYR` 51 B; `CLOK` 32 B; `SKY_` 4 B; `TEXT` four length-prefixed strings; `SECT` 4 B per section plus count.
- Per-stack cost is 43 B plus the custom-name length ([`game_save.cpp:14-28`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/game_save.cpp#L14-L28)). Per `RefChanges` entry the floor is 28 B plus 8 B per faction row and 4 B per option that is present ([`:294-314`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/game_save.cpp#L294-L314)). Per seen cell: 12 B + 32 B of grid words ([`local_map.cpp:100-108`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/local_map.cpp#L100-L108)). Per VM object: 29 B plus its variables; per VM stack frame: function id (12 B), self value, object id, `ip`, slots.
- Therefore a save is O(changed state), not O(world). A rough arithmetic estimate for a played character (300 inventory stacks, 2,000 changed refs, 60 containers, 1,000 VM objects spread over 30 scripts) is 150-400 KiB. This is my arithmetic from the field lists, **not measured**.
- Speed: the frame cost is the gather, which serializes every changed map on the main thread. The disk write is off-thread. The load cost includes `load_world(space)` and `Game::load` on the main thread ([`app_saves.cpp:796`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L796), [`:812`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L812)), so a load can stall one frame; the screen hides it. The loading screen is deliberately held for at least 3000 ms for a save load ([`app_menus.cpp:867-871`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_menus.cpp#L867-L871)), so "sub-second load" is not a design goal here — perception is.

### What is not persisted

Evidence is [`game.hpp:534-615`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/game.hpp#L534-L615) and `app_internal.hpp` member lists: a member that no `save` function writes is not persisted.

- Everything physical and transient: actor animation state, ragdolls, physics body velocities, projectiles in flight, impact decals, VFX, sounds, water state.
- Combat and AI runtime: combat targets, combat AI decisions, detection events, idle/loose-idle state, AI packages in progress. Only an agent's space, position, heading, scale, disabled flag and detach hours are saved ([`game_save.cpp:532-552`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/game_save.cpp#L532-L552)).
- Mount state (`MountState m_mount`, [`app_internal.hpp:1067`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_internal.hpp#L1067)) and riding. A save made while riding reloads on foot.
- Player furniture/sit state (`m_player_sit`, `m_player_furniture`, [`game.hpp:546-547`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/game.hpp#L546-L547)), ash piles (`m_ash_piles`), blocked refs (`m_blocked`), notices (`m_notices`), VATS (`m_vats`), camera paths (`m_camera_paths`), tempering temporaries.
- Dialogue and conversation state, the current speaker, scene playback, subtitle timing.
- Menus, selection, console history, tutorial *popup* state beyond the shown list.
- The loaded cell set, streamed meshes, LOD, textures, and the render state.
- Weather transition progress (only the target weather id), time-of-day interpolation, precipitation.
- Any plugin content. Deliberate: an `.ost` "holds no content" ([`ost.hpp:5`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/ost.hpp#L5)).
- Character creation/appearance beyond race, sex and beast flags; facegen data is not stored.
- Crime's `m_crimes` witness list *is* saved, but the *active* dialogue-driven bribe/intimidate session is not.

Phase 4.4 is a plan (`docs/roadmap/04-gameplay-and-physics.md:24-28`). The mapping below therefore names the module that should own each ledger group and what it needs from the converter.

Do **not** copy spud's exact-equality gate ([`ost.cpp:67`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/ost.cpp#L67)), which makes every schema change a hard failure |

| Corruption handling | Runtime errors surface as `Result`; no save path | Validation and recovery | `crates/engine/src/save/validate.rs`: checksum per section, bounded readers, and a quarantine path. Copy spud's per-file corrupt flag idea, not its uncaught `finish_load` |

What the converter must provide for any of this: stable FormKeys per record; a plugin table with name, flags, header version, masters and content hash (already decided in #542/PR #552); and cell/ref ownership so a save delta can be grouped by cell. The converter does not need to produce save data.

Design conflicts to settle before implementation:

1. **Storage backend.** #90 proposes a git repository of override commits; Phase 4.4 proposes SQLite delta rows in `skyrim_world.db`. These are different durability models. Git gives rollback and history but costs a commit per save; SQLite gives sub-second writes but needs an explicit history policy. A defensible split is SQLite for the live delta and an optional exported commit for archival, but that is a decision, not a finding.
2. **Immutable world database.** Phase 4.4's wording ("Delta state tracking written to SQLite database (`skyrim_world.db`)") conflicts with the project rule that converted packs are immutable. Saves need their own database file, e.g. `saves/<character>/skyrim_save.db`, with the world DB opened read-only.
3. **Stack-resume fidelity.** Skyrim and spud resume suspended Papyrus stacks mid-function. Luau has no equivalent stable bytecode frames. Mudcrab must choose between (a) re-running an event after load, (b) designing scripts so all persistence lives in tables, or (c) accepting dropped stacks. This is the single largest parity risk in 4.4.

Minimal vertical slice that proves the subsystem (Mudcrab):

Fixture: one interior cell from the unmodded install, one movable clutter reference, one container, one actor, one quest with two stages, one Luau script with a table-valued property and one suspended `RegisterForUpdate`.

1. Start, move the clutter to a known transform, take one item from the container, advance the quest one stage, increment the script counter, save.

## Open questions

1. Does Skyrim reject a save whose plugin list changed but whose FormIDs still resolve? I did not verify the native rule; spud's behaviour (silent) is unverified against vanilla. Cheapest check: load a save after adding a plugin that shifts slots, in the vanilla game.
2. Vanilla's exact obsolete-save rule (what version fields it compares) is unknown to me. `SaveDetails::obsolete` in spud is dead code, so the comparison cannot be inferred from the code.
3. Is `m_play_seconds` intended to include menu time? [`app.cpp:466`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app.cpp#L466) says "real time, menus included", which differs from Skyrim's play-time counter if that excludes menus. Unverified.
5. The save list, Continue, and the next manual number all use the file's mtime ([`app_saves.cpp:481`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L481), [`:500-503`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L500-L503), [`:605`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L605)), not `Header.saved_at`. A save copied or restored from a backup therefore changes "newest". Whether that matches vanilla is unverified; the header field exists but is only displayed ([`:550-553`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L550-L553)).
6. Is dropping a VM stack on a missing function acceptable to spud's author? The file header ([`vm_save.cpp:5`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm_save.cpp#L5)) says the game resumes from a copy and spud drops it, so the deviation is acknowledged but not explained.
7. No measured save size or gather time exists in the repository. A single instrumented run would settle both; I could not run it (read-only task).
8. Mudcrab issue #567 had not been read when this report was written. Its content may change the Phase 4.4 mapping.
9. Whether Mudcrab should adopt a git-backed store (#90) or SQLite deltas (Phase 4.4) is undecided in the documents I read; both are proposals.
