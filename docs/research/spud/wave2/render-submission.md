## Architecture

Spud is a hand-written Vulkan 1.3 renderer: dynamic rendering, synchronization2, buffer device address, one 65536-slot descriptor set per frame in flight, two frames in flight, one command buffer and one `vkQueueSubmit2` per frame. There is no render graph and no GPU-side indirect count anywhere: every draw command is written on the CPU into a per-frame arena buffer, and one `vkCmdDrawIndexedIndirect` covers a contiguous run of them ([`renderer.cpp:591`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L591), [`renderer.cpp:579-594`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L579-L594)).

```

  wait slot fence ..................................... vkAcquireNextImage (1165)
  read last timestamps (2 frames late)                 reset fence+pool, begin cmd (1177-1183)
  bindless->begin_frame(slot): flush queued slots       stamp(); init offscreen (1186-1188)
  collect_garbage (deferred frees by frame serial)      |
  uploader->poll(budget)  <- transfer-queue timeline     |  [door far frame first: same code, scissor, m_far_pass]
  textures->update, meshes->update                      |
  free slot's old arenas                                +-> compute: skinning (986) + skin decals (1074)
                                                        +-> sun shadows, volume, light shadows (1302-1310)
                                                        +-> ONE dynamic-rendering scope into HDR+normals (1339-1482)
                                                        |     opaque -> terrain -> alpha -> 2nd pass
                                                        |     -> grass -> far trees -> sky
                                                        +-> depth copy/resolve (1485-1512)
                                                        +-> AO -> decals -> scene copy -> SSR -> snow
                                                        |     -> composite -> water (1519-1578)

                                                        |     decals, particles, precipitation (1587-1645)
```

Diagram source lines: [`src/render/renderer.cpp:476`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L476).

Ownership and threading: `Renderer` owns the `Device`, a `JobSystem`, the `Uploader`, `TextureManager`, `MeshManager`, `Bindless`, two `Pipelines` sets and all targets ([`renderer.hpp:361-375`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.hpp#L361-L375)). Two threads matter: the render thread (everything above) and a dedicated upload thread that copies into a chunked staging ring, records transfers on the transfer queue and signals a timeline semaphore; the graphics submit then waits on the value the render thread has already observed, so the wait never stalls ([`uploader.hpp:3-12`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/uploader.hpp#L3-L12), [`uploader.hpp:66-70`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/uploader.hpp#L66-L70), [`renderer.cpp:1900-1906`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L1900-L1906)). Background jobs only build CPU data; a job's GPU-visible effect is deferred to a callback run from `Uploader::poll` on the render thread ([`uploader.hpp:42-43`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/uploader.hpp#L42-L43)). Destruction is deferred by frame serial: `Device::defer` records a function against the recording serial and `collect_garbage` runs it once that serial has completed ([`device.hpp:112-120`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/device.hpp#L112-L120), [`renderer.cpp:484`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L484), [`renderer.cpp:492`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L492)).

Lifecycle: construction builds the device, then arenas whose capacity is a clamped fraction of the VMA budget (vertex `budget/16` in 256 MiB..1536 MiB, index `budget/32` in 128..768 MiB, textures `budget/3` in 512 MiB..10 GiB) ([`renderer.cpp:150-162`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L150-L162)). Targets are created per extent, destroyed on resize after `wait_idle` ([`renderer.cpp:392-404`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L392-L404), `368-385`). Teardown calls `drain()` (wait jobs, drain uploads, `device->wait_idle`, flush deferred frees) before destroying anything ([`renderer.cpp:284-296`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L284-L296)).

Descriptor model: binding 0 is a 65536-element `SAMPLED_IMAGE` array indexed by `TextureId`, binding 1 is an array of 6 immutable samplers, one set per frame in flight, `PARTIALLY_BOUND` so slots may be unwritten ([`bindless.hpp:3-7`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/bindless.hpp#L3-L7), [`bindless.cpp:44-64`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/bindless.cpp#L44-L64)). The top of the array is reserved for render targets and the image-space chain by explicit slot constants ([`bindless.hpp:34-79`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/bindless.hpp#L34-L79)). A slot write goes into the frame being recorded at once and is queued for the other sets; when a set's turn comes, queued writes are sorted by slot and only the last write per slot is applied, because a resize may already have destroyed an earlier view ([`bindless.cpp:108-157`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/bindless.cpp#L108-L157)).

Mesh submission: all mesh vertex and index data live in two shared device buffers suballocated by `GpuArena`, so one vertex-buffer binding and one index-buffer binding serve every mesh ([`gpu_arena.hpp:3-4`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/gpu_arena.hpp#L3-L4), [`renderer.cpp:1405-1410`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L1405-L1410)). Per frame, `build_mesh_draws` counts instances per (draw group, LOD), buckets groups by packed draw-state slot, sorts the buckets by state value, writes one `VkDrawIndexedIndirectCommand` per (group, LOD) with the exact instance count, and emits one run per bucket ([`renderer.cpp:642-786`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L642-L786)). Blended draws are one command each, sorted back to front by camera distance squared with submission order as tie-break ([`renderer.cpp:738-760`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L738-L760)).

Every per-frame value the shaders read is reached through one 128-byte push-constant block of 64-bit buffer device addresses plus a mode word and four pass words ([`gpu_types.hpp:274-292`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/gpu_types.hpp#L274-L292)); the block is pushed once per rendering scope and re-pushed around the few passes that need extra addresses ([`renderer.cpp:1284-1297`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L1284-L1297), `1400`, `1439-1449`, `1546`).

Image history: the renderer keeps no final-image history, and enforces that structurally. Every scene target is created as `Lifetime::frame` with a comment that nothing in it may be read by the next frame ([`renderer.cpp:316-317`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L316-L317)); each frame's first use transitions those targets from `VK_IMAGE_LAYOUT_UNDEFINED`, which discards previous contents ([`renderer.cpp:1318-1330`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L1318-L1330)). Cross-frame state is allowed only for named effect resources declared `Lifetime::simulation`/`Lifetime::cache`, and an allowlist in the device throws at creation if the debug name is not on it ([`device.hpp:24-33`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/device.hpp#L24-L33), [`device.cpp:519-534`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/device.cpp#L519-L534)). The eight allowlisted names are `local map`, `eye adaptation`, `precipitation occlusion`, `water history`, `water reflection`, `water flow`, `water ripples`, `skin decals` ([`device.cpp:519-522`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/device.cpp#L519-L522)).

## Port notes

Pitfalls and hidden coupling, in the order they would bite a port.

1. **Slot capacity is not draw cost on Metal.** `multi_draw_indexed_indirect(args, offset, max_count)` costs one Metal `drawIndexedPrimitives` per slot in wgpu-hal; zero-instance records still iterate (`docs/research/profiling-measurement-validity-20261008.md:19-22`). Mudcrab's cluster renderer takes exactly this path when `MULTI_DRAW_INDIRECT_COUNT` is absent (`crates/engine/src/cluster/render.rs:2310-2313`, `3872-3876` @ an unmerged local branch), and its comment claims the empty tail is free. That comment is wrong on Metal. A 34.5 GiB cluster working set on Apple Silicon is consistent with a per-slot encode and transient allocation (measured locally; receipt not in the repository — **unverified** here), and #533's own text gives 5.5–8.3 million slots per pass, six passes, 5–12 GB per frame.
2. **The cheapest fix is spud's, not #533's — if the CPU still knows the visible set.** Spud writes exactly the commands it will draw and issues one indirect call per state bucket ([`renderer.cpp:585-591`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L585-L591), `695-715`). No capacity, no empty tail, no vertex pulling, no NaN padding vertices. It gets there because Skyrim's draw list is built on the CPU, so the instance counts are known before submission. Mudcrab's cluster path deliberately moved selection to a compute pass (PR #441), so the CPU does not know the selected groups and cannot write exact counts without a readback. The three Metal-safe options are therefore: (a) keep GPU selection and take #533's one-draw-per-group path; (b) keep GPU selection and compact the *count* into a single draw via a per-group indirect record with `first_instance`/`instance_count` written by the cull (which is what #533 does); (c) drop GPU selection for a CPU-built list, as spud does, which costs a CPU pass and loses the GPU cull. `unverified`: which of these is cheapest on an M-series GPU has not been measured.
3. **Positional pass timestamps are fragile.** `stamp()` is a side-effecting lambda with a hidden far-pass early return ([`renderer.cpp:1186`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L1186)), pass indices are kept aligned by dummy calls (`1576-1578`, `1877-1879`), and a not-ready result drops the frame silently (`445-447`). Any port that copies this shape will mis-attribute passes the first time a pass is added. Use named scopes and a stable per-pass index derived from the enum.
4. **Query readback lag must be modelled, not hidden.** Two frames in flight means timings describe frame N−2 ([`renderer.cpp:437-456`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L437-L456), `468-474`). Mudcrab refuses to attribute a frame to GPU passes for exactly this reason (`crates/engine/src/frame_budget.rs:38-40`). Keep that refusal.
5. **`UNDEFINED` is doing the work the doc claims.** "No history" is enforced by discarding each scene target at first use every frame ([`renderer.cpp:1318-1330`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L1318-L1330)) plus a `Lifetime::frame` declaration that is *trusted* ([`device.cpp:524-527`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/device.cpp#L524-L527)). The declaration alone proves nothing; the barrier is the mechanism, and `history_audit.py` is the proof. A Bevy port has no `UNDEFINED`; the equivalent must be `LoadOp::Clear` on every target the pass owns, or a fresh texture.
6. **The allowlist matches names, not resources.** `check_lifetime` compares the debug-name string ([`device.cpp:519-537`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/device.cpp#L519-L537)). Any future resource called `water history` passes. Fine as documentation, useless as a gate.
7. **The audit's 1 % tolerance is a policy, not a measurement.** `MAX_DIFF_SHARE = 0.01` ([`history_audit.py:44`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/tools/audit/history_audit.py#L44)) lets a real but small history dependence pass, and the diff message prints `(within the limit)` (`236`). The comment says the limit is the user's call (`42-43`). For Mudcrab, 0 % on a deterministic scene is the defensible default, with named exceptions.
8. **The audit compares LDR only.** `png_pixels` asserts 8-bit and accepts only colour types 2/6 ([`history_audit.py:87-97`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/tools/audit/history_audit.py#L87-L97)), and the screenshots are the swapchain-colour target. An HDR-only history dependence that the tonemapper hides is invisible. Spud has the machinery to compare HDR ([`renderer.cpp:1668-1691`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L1668-L1691)) but the audit does not use it.
9. **Time of day is unpinned in the audit.** Weather is fixed ([`history_audit.py:168`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/tools/audit/history_audit.py#L168)), the hour is not. The script's own comment calls the hour game state (`167-168`). A warm run leaves the clock at a different hour than a cold run unless the engine's clock is frozen by the script. `unverified`; if true, the audit is fail-safe (it fails) rather than fail-open.
10. **Budgets are keyed by a machine-name prefix and there is no Metal entry.** `machine_id` joins GPU and CPU names into a slug ([`perf.py:117-120`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/tools/perf/perf.py#L117-L120)); `budget_for` matches by prefix (`150-155`). On an M-series Mac, `budget_for` returns `None` and only the baseline regression runs (`364-365`). If Mudcrab adopts this schema for E2, an `apple-m*` block is required or the Metal numbers are unjudged.
11. **Contamination detection is Windows-shaped.** `gate.py` uses a named pipe ([`gate.py:44`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/tools/gate/gate.py#L44)), scans process names (`58-63`) and a GPU-busy counter (`135-164`); `perf.py` reads the flag file (`126-134`). None of that runs on macOS as written. Mudcrab's equivalent is the manual "no other GPU work, window unobscured" protocol in `scripts/profiling/README.md:65-71`, which is weaker but portable.
12. **Windows-only paths in all three tools.** `spud.exe` ([`perf.py:324`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/tools/perf/perf.py#L324), `191`), `LOCALAPPDATA` ([`perf.py:337`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/tools/perf/perf.py#L337)), `scripts\\audit.cmd`/`perf.cmd` (`scripts/perf.cmd:7`), dbghelp ([`sample_report.py:29`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/tools/perf/sample_report.py#L29)). Copying the *schema* is free; copying the scripts costs a rewrite.
13. **Constants worth knowing.** 2 frames in flight ([`vk.hpp:30`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/vk.hpp#L30)); 65536 texture slots with 71 reserved ([`bindless.hpp:34-79`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/bindless.hpp#L34-L79)); −0.25 LOD bias ([`bindless.hpp:17`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/bindless.hpp#L17)); 8 MiB minimum frame arena and 1.5× growth ([`renderer.cpp:425`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L425)); 48 completions / 96 MiB per-frame upload budget ([`renderer.hpp:180-181`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.hpp#L180-L181)); 60-frame hitch window and 2 ms floor ([`perf.py:30-32`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/tools/perf/perf.py#L30-L32)); 60 s quick suite ([`perf.py:35`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/tools/perf/perf.py#L35)); 5 and 150 frame audit windows ([`history_audit.py:49-52`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/tools/audit/history_audit.py#L49-L52)); 30-frame stability gap ([`history_audit.py:213`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/tools/audit/history_audit.py#L213)); 128 px portal scissor margin ([`renderer.cpp:1391`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L1391)); 4 shadow lights ([`renderer.cpp:919`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L919)); 8 allowlist names ([`device.cpp:519-522`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/device.cpp#L519-L522)).
14. **Ordering constraints that are load-bearing.** Descriptor writes for the slot run *after* the fence wait and *before* deferred frees, because a resize can destroy a view a queued write still names ([`renderer.cpp:485-493`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L485-L493), [`bindless.cpp:114-115`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/bindless.cpp#L114-L115)). Depth must be copied/resolved before water and blended draws read it (`1485-1512`, `1513-1518`). Volumetric light must add to the scene before refraction reads it (`1652-1667`). The pre-UI capture must precede offscreen views (`1850-1853`). The far pass must precede the main pass and must not advance the capture (`1819-1825`).
15. **Minimal vertical slice that proves the submission model.** Two runs of one fixture pose, same binary, same assets: (a) a cold process starting at the pose; (b) a warm process that flies in, waits 5 frames. Assert: the two PNGs are byte-identical (or differ in 0 pixels), the warm image is stable 30 frames later, and — on Metal only — the counted API draw calls equal the number of selected groups, not the slot count. That is one scene, one pose, three assertions, and it catches both the history bug and the slot-capacity cost.

### Measurement limits to carry into Mudcrab's acceptance

1. Allocated records ≠ issued commands ≠ pixels. Spud counts commands and instances it *wrote* ([`renderer.cpp:707`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.cpp#L707), `782-785`); it cannot see how many the driver encoded. Mudcrab already states the same distinction (`docs/research/profiling-measurement-validity-20261008.md:39-41`, `54-56`).
2. GPU pass timings are lagged by the frames in flight and may be absent; on Metal, Bevy's encoder timestamp writer returns early (`docs/research/profiling-measurement-validity-20261008.md:77-79`). Any per-frame GPU claim on Apple Silicon needs a native source (Mudcrab's `metal_trace.m` path), not pass timestamps.
3. The Metal HUD's duration spans command buffers and includes idle gaps (`docs/research/profiling-measurement-validity-20261008.md:88-95`); it is not a per-draw cost.
4. Image comparisons in this subsystem are LDR, 8-bit, one pose, 1 % tolerant ([`history_audit.py:44`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/tools/audit/history_audit.py#L44), `87-97`). They can miss an HDR-only or sub-1 % dependence.
5. A headless hidden window still presents ([`renderer.hpp:81-83`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/render/renderer.hpp#L81-L83)), so "headless" is not "GPU-idle-only": presentation cost is in the number unless the mode is stated. Mudcrab's rule is to record the resolved present mode, and that it is not currently a metadata field (`docs/research/profiling-measurement-validity-20261008.md:150-152`).
6. An unobscured window is required; an occluded window's frame rate is not comparable (`scripts/profiling/README.md:65-71`).
