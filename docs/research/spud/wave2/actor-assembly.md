## Architecture

Two objects, split by sharing and lifetime:

- `ActorData` ([`actors.hpp:181-342`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.hpp#L181-L342)) is process-wide, owned by the app, concurrent. It loads `forms.osf` ([`actors.cpp:194-195`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L194-L195)), indexes placed references on a background thread (`index()`, [`actors.cpp:204-269`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L204-L269)), and turns records into an `ActorLook` (`look()`, [`actors.cpp:1269-1522`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L1269-L1522)) and an `ActorSkeleton` (`skeleton()`, [`actors.cpp:490-508`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L490-L508)). Mutating script state (outfits, gear, face, beast race, level) is held in mutex-guarded maps ([`actors.hpp:304-341`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.hpp#L304-L341)).
- `ActorSet` ([`actors.hpp:394-879`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.hpp#L394-L879)) is one space's actors. `start()` launches `look()` on a background thread ([`actors.cpp:1544-1559`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L1544-L1559)); `update()` starts at most 8 actors per frame near the camera, finishes at most 4 (`k_start_per_frame`/`k_finish_per_frame`, [`actors.cpp:58-59`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L58-L59), [`actors.cpp:4033-4088`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L4033-L4088)), ends actors more than one cell beyond the grid radius ([`actors.cpp:4044-4053`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L4044-L4053)), and poses them. Geometry becomes `render::MeshId` + per-part variant (`Part`, [`actors.hpp:644-656`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.hpp#L644-L656)); poses become flat `glm::vec4` bone rows in `ActorData::skin_jobs/skin_bones` ([`actors.hpp:238-265`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.hpp#L238-L265)), consumed by the renderer (`SkinFrame`, [`actors.hpp:242-246`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.hpp#L242-L246)).

```
records (forms.osf)
   |                                importer (offline)
   +-- ARMA MOD2..MOD5 ---> skinned/.../<model>.osm  (skin + partitions + materials)
   +-- HDPT MODL/NAM1  ---> skinned/.../<head>.osm, skinned/.../<tri>.ofm
   +-- HDPT NAM1 (tri) ---> skinned/.../<tri>.ofm
   +-- RACE ANAM       ---> skinned/.../skeleton.osk  (+ project name from BSBehaviorGraphExtraData)
   +-- RACE NAM3 MODL  ---> animations/.../<project>.osb (read via anim::Project::load)
   +-- WEAP/ANIO/AMMO/Armour ---> skinned/.../*.osm  (rigid shapes, attach name "" )
   +-- facegendata/facegeom/**/*.nif ---> skinned/.../*.osm
   +-- facegendata/facetint/**/*.dds ---> texture deps only
                                      |
                                      v
ActorData::look(npc, ref)  ---------------------------> ActorLook
   traits root -> race, sex, skin ARMO, outfit, weapons, head           (32 fields, actors.hpp:85-118)
                                      |
                                      v
ActorSet::start -> async look -> update(): acquire meshes -> finish()
   finish_parts(): partitions -> index runs, texture swaps, tint, hair -> skinned_variant
   start_animation(): graph (project) or ObjectLoop (.ose) or no animation
   pose(): SkinJob per shape + RowBone plan -> pose_rows() -> skin_bones (3 vec4 per bone)
                                      |
                                      v
renderer: skin_frame(...) -> GPU skinning -> space instance table (Visual)
```

Threading and ownership rules that matter:

- `look()` runs on a background thread ([`actors.cpp:1553-1557`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L1553-L1557)) and reads `m_face_mutex`/`m_level_mutex` around mutable state ([`actors.cpp:1271-1279`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L1271-L1279), `1393-1405`).
- `project()` de-duplicates loading with a `shared_future` so two background threads never parse one graph twice ([`actors.cpp:511-536`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L511-L536)).
- `skeleton()` caches by path with a double-checked lock; a duplicate bone name keeps the first (`by_name.emplace`, [`actors.cpp:500-503`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L500-L503)).
- Assembly mutates `m_live`, `m_parts` and renderer state only on the main thread; `end()` abandons an in-flight `look()` future instead of waiting ([`actors.cpp:1570-1576`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L1570-L1576)).

| child NPCs (#470) | `spawn_plan` uses the composed body only when every part path equals `meshes/actors/character/character assets/{sex}{body,hands,feet}_1.nif` (`world/actor_catalog.rs:48-69`); otherwise it falls back to the catalog's `body` part via `converted_model_path` (`302-333`) | implemented with a gap | if a child body part path differs from those three shared paths (inferred; the child records were not read), the actor gets a single body GLB with no hands/feet; clips are attached only for the composed body (`streaming.rs:1884-1888`), so no gait clip is installed | converter must compose per-race bodies (or the engine must assemble parts); see Port notes |
| creatures (#471) | same path as children | implemented with a gap | creature body part is not the shared humanoid set, so no composed body and no clip; all three clips are humanoid names (`actor_animation.rs:50-60`) | needs per-race animation selection before B2 |
| #555, #512-#515 | issue text was not available when this report was written | unverified | scope of these issues was not read | confirm the issue numbers and scope before relying on them |

Against milestone B1 (humanoid, child, five creature families, correct body/head/skin, equipment attach, no T-pose), Mudcrab has the humanoid body and head path only. Child rigs, creature rigs, skin-part assembly beyond three slots, and equipment attach are all absent; the T-pose criterion cannot be met for any family until a per-race skeleton and clip selection exist.

Design fit, concretely:

- Rust ownership: an `ActorLook` struct mirroring spud's 32 fields is a natural `Component` or a `Resource`-cached value keyed by `(npc, sex, race, first_person)`; the converter already owns record resolution and should publish the resolved rows, as it does for the catalog today. Do not move rules into the engine that the catalog can encode once.
- Data needed from the converter: per-NPC gear list with resolved slots; per-race skeleton path and behaviour project; per-ARMA addon model paths, texture set, priority, `weapAdj`, footstep set; per-head part list with morph roles; per-weapon model and animation type; ANIO props. All are record fields; none needs a new binary format if the catalog tables grow.
- Bevy: spud's `Part` -> `ActorDraw` -> GPU skin rows maps to one `Entity` per part with a `SkinnedMesh` sharing the body skeleton, which is exactly what `actor_head.rs:1-20` already does for the head. The head rehost technique generalises to addons.
- glTF/pack: Mudcrab publishes GLB; spud publishes `.osm` with skin chunks. Equivalent information (joints, weights, inverse bind) exists in glTF; what glTF lacks is the dismember partition list and the "rigid shape attached at node X" convention, so the converter must encode both (for example as extras or a side table).
- No ADR covers actor assembly. `docs/roadmap/01-asset-pipeline.md:29,69` promises skinned NIF to GLB with `skins`/`joints`; `docs/roadmap/04-gameplay-and-physics.md:16` lists skinned clip playback. Milestone B1 closes the gap.

## Port notes

1. **Resolution is an offline job, not a runtime job.** Spud's `look()` walks many record chains per actor and re-runs on every `Reset`/`reroll`. Mudcrab's design already puts record resolution in the converter; keep it there, and store the resolved look (or the inputs to it) so the engine does not link a record reader. Re-run cost is the only reason spud resolves at runtime.
2. **The `_0`/`_1` pair is a single asset with two vertex sets.** Spud keys this on the filename tail ([`actor_import.cpp:37-50`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/importer/convert/actor_import.cpp#L37-L50)) and merges only when vertex and index counts match ([`mesh_import.cpp:1266-1280`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/importer/convert/mesh_import.cpp#L1266-L1280)). Mudcrab has the thin morph as a glTF morph target (`actor_body_weight.rs:1-6`, `pipeline.rs:2745-2757`), which is the same idea expressed in glTF. Keep that: one body GLB with a `thin` target beats two files.
3. **Three invisibility mechanisms exist; all are silent.** Zero-scale bone rows, variant-pool exhaustion, and skipped addon models. A Mudcrab port should emit a typed diagnostic for each, otherwise B1 acceptance cannot distinguish "not equipped" from "lost".
4. **Ordering constraint: partitions before variants.** The index runs and material edits must be computed before `skinned_variant` ([`actors.cpp:1644-1745`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L1644-L1745)); a variant is shared per (mesh, ranges, edit). Plan the Rust side as a cache key of (mesh, visible partition set, texture overrides, tint) or you will allocate one material per actor.
5. **Head slot is all-or-nothing in spud.** A worn helmet returns before any head ([`actors.cpp:1475-1479`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L1475-L1479)). Vanilla hides only covered parts. This is a visible liberty; a port should not repeat it.
6. **Hair colour is doubled at load** ([`actors.cpp:1260-1265`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L1260-L1265)) and the shader expects the doubled convention. Mudcrab's `skin_material.rs:40-45` describes exactly that convention for `HAIR_TINT`, so the converter must publish the doubled value or the engine must double it once. Doubling twice gives blown-out hair.
7. **The FaceGen tint map is bound to the height slot** (`gtex_height`, [`actors.cpp:1719-1723`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L1719-L1723)). That is a slot-convention detail of spud's material model, not a Skyrim rule; Mudcrab's `skin_material.rs:9-20` documents its own slot-105/106 layout and should not copy the slot number.
8. **`weapAdj` changes poses.** It starts at `weight * 0.5` and adds each non-lone addon's adjust ([`actors.cpp:1434-1444`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L1434-L1444)). If Mudcrab's animation path ignores it, weapon poses will be wrong in a way that looks like a rig error.
9. **First person is a second full body.** `k_player_ref` and `k_player_first_person_ref` are separate actors ([`actors.cpp:20-22`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L20-L22), `3652-3656`), with a fixed rig and a fixed project. Budget for two bodies when planning memory.
10. **Animated props are parts, not entities.** `AnimObjLoad` adds a part to the actor ([`actors.cpp:3939-3966`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L3939-L3966)). In Bevy this is a child entity with the actor's skeleton; the ANIO unload tag is per prop, and props stay loaded after being folded away.

Minimal vertical slice that proves the subsystem:

- Fixture: one male Nord (`00013475`, Alvor) and one child NPC and one wolf, in one interior, with the player absent.
- Check A (assembly): actor entities have a body, hands, feet and head drawable; part bounds non-empty; total part count and per-slot masks match a recorded expectation.
- Check B (no T-pose): after 1 s of idle, at least one bone's world transform differs from its rest transform by more than 1e-3 for the Nord; for the child and the wolf the same check runs, and a failure is reported as a typed diagnostic rather than a silent rest pose.
- Check C (head): the FaceGen head's joint list names the body's joints (`actor_head.rs` behaviour) and the head draws at the neck, not at the origin.

## Test ideas

Deterministic, headless:

1. **Catalog golden test.** Run `resolve_actor_models` over a fixture record map and compare rows, part rows, and diagnostics. Mudcrab already has this shape (`actor_models.rs:620-658`); extend it with child, wolf, and a female with a `WNAM` override.
2. **Model enumeration test.** Feed a synthetic DataSource listing (ARMA with four `MODL`, HDPT with `NAM1`, RACE with two `ANAM`) and assert the exact output set of `.osm`/`.osk`/`.ofm` names, including the `_0`/`_1` collapse. This mirrors spud's importer with no engine needed, and is the cheapest parity oracle for the port.
3. **Skeleton rest-pose test.** One `.osk` fixture with a three-bone chain; assert `rest[i] = rest[parent] * rest_local[i]` and that a duplicate bone name resolves to the first index.
4. **Partition selection test.** A synthetic skinned mesh with partition ids `30, 31, 130, 230`; assert the visible index ranges for a slot mask, a head mask, and `hair_worn`.
5. **Head precedence test.** NPC `FTST` set, race `DFTM`, part `TNAM`, and `CNAM` hair colour; assert chosen texture paths and doubled hair colour.
6. **Weapon scoring test.** Two swords and one bow with known damage/speed; assert the right hand is the highest melee DPS and the bow is spare past the geared-up count.
7. **Footstep material test.** Synthetic raycast hit with a known havok material, and a miss outdoors with a dominant land texture; assert the resolved material and the silence case.
8. **Event routing test.** Inject `weaponDraw`, `AnimObjLoad`, and a footstep tag; assert the part's `weapon_drawn` flips, the prop part appears, and one footstep is requested per distinct `FSTS`.

## Open questions

1. Which child skeleton and body parts does the retail child race name? Spud has no child branch, so its success depends entirely on `ANAM`/`MOD2` correctness. Cheapest check: read the child `RACE` record's `ANAM` and one child NPC's skin armour from a converted database.
2. Does Mudcrab's mesh stage convert the body part NIF a non-shared actor falls back to? `converted_model_path` builds a path without an existence check (`streaming.rs:4548-4576`). Cheapest check: query the conversion manifest for a child body `.glb`.
3. How does vanilla pick between two addons of equal priority in one slot? Spud uses `swap_list` as an extra tie-break ([`actors.cpp:178-186`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L178-L186)); this is unverified against the engine.
4. Is `weapAdj` the only pose-affecting addon field? Spud reads `DNAM.weapon_adjust` and nothing else here; a second field would be a silent omission.
5. Are the technique-byte mappings `4` (FaceGen skin), `5` (tint), `6` (hair), `16` (eyes) stable across vanilla head NIFs? `unverified`; they come from spud's shader-type handling, and the render side was not read.
6. Do lip tracks and blink work end to end? The types and the `speak()` call exist ([`actors.hpp:657-680`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.hpp#L657-L680), [`actors.cpp:1997-2031`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L1997-L2031)), but the animation side was not read.
7. Are issues #555 and #512-#515 real numbers? Their text was not available when this report was written, so their scope was not verified.
8. What does the engine do for a race whose `NAM3` has only one graph entry but the actor is female? Spud indexes `[1]` only when `size() > 1` ([`actors.cpp:1326-1327`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actors.cpp#L1326-L1327)); whether vanilla has a female-only graph case is unverified.
