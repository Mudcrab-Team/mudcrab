## Architecture

Spud separates rules from the world twice, with a pure-virtual interface per domain. Both interfaces default to "nothing is there", so a missing host is a silent no-op, not an error ([`combat.hpp:145-190`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/combat.hpp#L145-L190), [`magic_target.hpp:99-156`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/magic_target.hpp#L99-L156)).

```
                    ESM records (forms::Database, path-addressed Values)
                     |                    |                     |
             game/items.cpp        game/magic.cpp        game/crafting.cpp
             Item (kind, DNAM..)   Spell, MagicEffect    temper/improve
                     |                    |                     |
   game/inventory.*  |        game/magic_target.*  (per-ref effect lists)
   Stack + ItemExtra |        MagicTarget: has_spell, add_target, update
                     |                    |
   game/equip.cpp ---+--> Game::select/equip_hand/equip_spell
                     |                    |
   game/combat.cpp --+--> Combat: Fighter per ref, Gear, HitData, formulas
                     |                    |
        +------------+-----------+--------+
        |                        |
  CombatWorld (36 defaults)  MagicWorld (49 defaults)
        |                        |
  src/engine/app_combat.cpp: EngineCombat / EngineMagic
        |                        |
  ActorSet (3D body, animation graph, weapon nodes) | AI Agent | Papyrus | audio | VFX | physics
```

Threading and ownership: everything is single-threaded and frame-stepped from `App::update_combat` ([`app_combat.cpp:999-1044`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_combat.cpp#L999-L1044)), which calls `update_telekinesis`, the dying/`OnDeath` deferral, weapon-speed graph writes, the player's `Fighter` mirrors ([`app_combat.cpp:1031-1037`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_combat.cpp#L1031-L1037)), then `Combat::update(dt)` and `CombatAi::update(dt)`, then `update_attack_input`. Magic runs from `Game::update_magic` (declared [`game.hpp:166`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/game.hpp#L166)), which is outside this read.

Ownership: `Combat` owns `m_fighters` ([`combat.hpp:313`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/combat.hpp#L313)), keyed by reference form ID, and caches decoded attack lists in `m_attacks` ([`combat.hpp:314`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/combat.hpp#L314)). `MagicTarget` owns the effect vector ([`magic_target.hpp:263`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/magic_target.hpp#L263)); `Game::magic_target(ref)` creates one on demand for actors and objects ([`game.hpp:157-160`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/game.hpp#L157-L160)). `Inventory` owns stacks by value ([`inventory.hpp:66`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/inventory.hpp#L66)), with the player's owned by `Game::m_player` and containers by `Game::container(ref)` ([`game.hpp:354`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/game.hpp#L354)).

Data flow of one melee hit, end to end:

1. Input press → `ActionRightAttack` action → idle tree picks an event ([`app_combat.cpp:1131`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_combat.cpp#L1131)) → `Combat::attack_started` maps the event to `AttackData` and an `AttackState` ([`combat.cpp:365-407`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/combat.cpp#L365-L407)).
2. The animation graph raises `HitFrame` (`app_combat.cpp` → `Combat::animation_event` at [`combat.cpp:409-417`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/combat.cpp#L409-L417)) → `weapon_hit_frame` ([`combat.cpp:1103-1157`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/combat.cpp#L1103-L1157)).
3. `find_target` uses reach, cone and `high_actors` ([`combat.cpp:1060-1101`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/combat.cpp#L1060-L1101)); a miss falls back to a physics ray (`swing_pick`, [`app_combat.cpp:323-350`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_combat.cpp#L323-L350)) and an impact on the object it hits.
4. `hit_target` → `weapon_effects` (perk spell, enchantment, poison) → `populate_melee` (base damage, crit, sneak, armor, block) → `resolve` → `apply_hit` → `damage_health` → `kill`.
5. `kill` → `CombatWorld::died` ([`app_combat.cpp:286-312`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_combat.cpp#L286-L312)) → ragdoll, `OnDying`, `OnDeath` after 10 s ([`app_combat.cpp:1005-1014`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_combat.cpp#L1005-L1014)), story event `KILL`, crime report.

Lifecycle notes:

- `Fighter` is created lazily on first touch and its `ActorValues::derive` hook for armor is installed there for non-player actors ([`combat.cpp:60-75`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/combat.cpp#L60-L75)). A deleted or dead actor keeps its `Fighter`; nothing prunes `m_fighters`.
- `Combat::update` only ages cooldowns, bleedout regeneration, stagger and kill-move timers, and friend-hit memory ([`combat.cpp:140-177`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/combat.cpp#L140-L177)). It does not tick regeneration of health/stamina; that is `ActorValues`/`Character`.
- Magic effect lists are updated elsewhere (`Game::update_magic`), with a re-entrancy guard `m_updating` ([`magic_target.cpp:1272-1293`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/magic_target.cpp#L1272-L1293)).

## Port notes

Pitfalls and hidden coupling found while reading:

1. **Two world interfaces, all-defaulted.** Both `CombatWorld` (36 virtuals) and `MagicWorld` (49) return "nothing" by default. Every ledger row that says "host default no-op" is a silent failure mode. Mudcrab's milestone rule 2 forbids silent fallbacks; make the equivalents `Result` or a counted diagnostic, not `bool`.
2. **Perks are player-only.** Two one-line functions decide it ([`combat.cpp:50-56`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/combat.cpp#L50-L56), [`magic_target.cpp:71-73`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/magic_target.cpp#L71-L73)). If Mudcrab copies this shape, every NPC formula is wrong in a way no test will notice unless the fixture includes an NPC with a perk.
3. **`Fighter` carries mutable state that graphs also own.** `weapon_drawn` is written by the host ([`app_combat.cpp:1127`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_combat.cpp#L1127)), by AI ([`combat_ai.cpp:213`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/combat_ai.cpp#L213)), by a native ([`character_natives.cpp:351`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/character_natives.cpp#L351)) and by the player controller ([`app_player.cpp:792`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_player.cpp#L792)). Four writers for one bool is a race waiting to happen; in Bevy, make it a single `Equipment`-derived value.
4. **One-frame caches.** `Combat::replaced_item` is set and cleared around a graph action ([`app_combat.cpp:1087`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_combat.cpp#L1087), [`:1108`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_combat.cpp#L1108)) so the animation graph can read what a hand held before the equip. Any port must keep the write and the read in the same frame or the force-equip branches misread.
5. **Ordering inside a hit.** `hit_event` (`OnHit`) fires before damage ([`combat.cpp:1413`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/combat.cpp#L1413) vs `1433`), so scripts see pre-hit health. `predict_fatal` runs before the hit and is allowed to be wrong. Death, `OnDying`, `OnDeath` are separated by 10 seconds of ragdoll ([`app_combat.cpp:302`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_combat.cpp#L302), [`:1005-1014`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_combat.cpp#L1005-L1014)).
6. **Left/right is three different things.** `Worn::left/right/both` ([`inventory.hpp:28`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/inventory.hpp#L28)), `CastingSource` left/right ([`magic_target.hpp:21`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/magic_target.hpp#L21)), and `hand 0 = right, 1 = left` in equip ([`equip.cpp:108-110`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/equip.cpp#L108-L110)). They do not agree by name; a port that unifies them must convert at one boundary.
7. **Constants worth carrying, with provenance.** `fCombatDistance` 128, `fCombatHitConeAngle` 35, `fCombatBashReach` 128, `fStaggerMaxDuration` 3, `fKnockbackForceMax` 512, `fCombatKillMoveDamageMult` 10, `fBleedoutRate` 15, `fBleedoutDefault` 0.2, `fMagicUnitsPerFoot` 22, `iMaxSummonedCreatures` 1, `fCloakEffectUpdateInterval` 0.5. These are fallbacks in spud, not measured values; #264 should decide the source.
8. **Unit boundaries.** Damage is in game units; knockback is converted from Havok units at the trap event ([`app_items.cpp:1407-1420`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_items.cpp#L1407-L1420), factor 69.991249), and physics uses metres (`units::k_skyrim_unit_m`). Mixing them silently scales damage.
9. **A spell's effect list is copied by index and written back** ([`magic_target.cpp:1280-1290`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/magic_target.cpp#L1280-L1290)). Starting one effect can add others, so a port that iterates a live list will skip or double-tick effects.
10. **Console-only shortcuts exist and bypass rules.** `game cast` calls `apply` directly and `game ready` forces `weapon_drawn` ([`app_items.cpp:1990-2004`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_items.cpp#L1990-L2004)). Useful as a fixture harness; do not mistake it for a cast path.
11. **Saving.** `MagicTarget::save` writes nothing but the effect list, because values are already written ([`magic_target.hpp:211-213`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/magic_target.hpp#L211-L213)). A port that recomputes values on load will double-apply them.
12. **Licence.** Keep the MIT notice if any code is adapted; `docs/AI_POLICY.md` requires a human owner per line, so preference is reimplementation from this description.

The minimal vertical slice that proves the subsystem, adapted to Mudcrab:

- Fixture: dummy-content plugin with one NPC_ (bandit class, 100 health, mass 1), one WEAP iron sword (damage 9, speed 1, reach 1, skill One-Handed, stagger 0.75), one WEAP hunting bow plus one AMMO iron arrow, one ARMO iron cuirass, one SPEL firebolt (fire-and-forget, aimed, one damage effect, magnitude 25), one MGEF for it, and a GMST set with every `fCombat*`/`fDamage*`/`fStagger*` value the formula reads.
- Scene: player at origin facing north, bandit 96 units north, both on one navmesh triangle.
- Checks, each a headless assertion: (a) one sword swing removes exactly `weapon_base` × mitigation health and fires `OnHit` once; (b) a blocked swing removes `1 - percent_blocked` and consumes `block_stamina`; (c) a bow shot at the same range removes projectile damage and consumes one arrow; (d) a firebolt removes the spell's magnitude and applies no armor; (e) health reaching 0 emits `OnDying` then `OnDeath` once, and the actor's `LifeState` is dead; (f) an essential actor at the same blow goes to essential-down and stands up after the threshold, with no `OnDeath`.

## Test ideas

Deterministic, headless, and independent of rendering. Each names the fixture data it needs.

1. **Formula table test.** For 20 rows of `(weapon damage, temper health, skill, attack mult, armor rating, block percent, difficulty)` compare Mudcrab's result with a hand-computed value transcribed from the retail formula, with the GMST source named per row. This is exactly the C3 exit criterion. Fixture: none beyond a GMST set.
2. **Armor curve monotonicity and cap.** Sweep armor rating 0..1000 in steps of 25 and assert monotone decrease of damage and a hard cap at the configured maximum. Fixture: GMST set only.
3. **Event order trace.** Record the sequence `OnHit`, health change, `OnDying`, `OnDeath`, `OnCombatStateChanged` for one killing blow and compare with a golden list. Fixture: the encounter above.
4. **Essential and protected matrix.** 2×2×2 over (essential, protected, player killer) asserting death, essential-down, or nothing. Fixture: three NPC_ variants.
5. **Stack identity and transaction.** Add two stacks of one form with different owners and different temper health; remove half; assert quantities, extras, and the listener event order. This is the #563 "smallest check" from the draft issue, made concrete.
6. **Equip conflict matrix.** For every pair of (two-handed weapon, shield, torch, spell, bow, ammo) assert which hand each ends in and what comes off, against a table. Fixture: 6 items and one EQUP set.
7. **Sneak and crit determinism.** Inject a fixed RNG and assert the crit flag for a given `critAV` and `condition`, including the melee 0.2 vs projectile 1.0 factor, so a future "fix" is a deliberate change.
8. **Archetype coverage ledger as a test.** Enumerate all 47 archetype ids; assert each is either implemented or listed in an explicit unsupported list. This converts spud's six silent archetypes into a failing test at home.
9. **Effect taper and stacking.** Apply a 10 s effect with a 2 s taper, step 0.25 s, assert the magnitude curve and that a second cast replaces rather than stacks; then the same with a `stacks` archetype.
10. **Summon limit.** Cast three summons with `iMaxSummonedCreatures = 1` and assert the oldest ends first and the commander link is cleared.
11. **Condition function coverage.** For every condition id in the fixture data, assert the evaluator answers or reports "unknown" with a count; combat's 25 ids are a subset of this.
12. **Save round trip.** Apply a permanent buff and a temporary one, save, load, assert values identical and the effect list not double-applied ([`magic_target.hpp:211-213`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/magic_target.hpp#L211-L213)).

Fixtures to extract from vanilla data: one iron weapon, one steel shield, one bow and arrow, one fire-and-forget damage spell, one concentration spell, one calm effect, one summon, one disease, one soul gem and one filled variant, and the GMST blob. All are small records; they can be authored in `dummy-content` rather than extracted, which keeps the test independent of an install (`crates/dummy-content` already generates items and magic for the converter tests).

## Open questions

1. Where do the GMST values come from at runtime? Spud reads every GMST record ([`settings.cpp:7-23`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/settings.cpp#L7-L23)); Mudcrab publishes only two GMSTs (checked 2026-11-14). Is a `gmst` table an acceptable addition to the world database, or does `#264` plan a generated constants module?
2. Which module owns actor values: a new `game/actor_values.rs`, or an extension of `world/actor_catalog.rs`? The catalog today is model-only (`actor_catalog.rs:25-101`).
3. Does `crates/scripting` (Phase 3, `architecture.md:66`) take the native surface, and therefore the item and magic natives, out of `engine`? That decides where `AddItem` lives.
4. Is `records.data` blob decoding at load acceptable for combat, or must the converter publish typed tables? The current `records` table is the only path to WEAP/SPEL data and it is opaque (`crates/converter/src/esm/exporter.rs:143-147`).
5. `#542` will change form identity. Do stacks key on a 64-bit FormKey from day one, or on a 32-bit id with a migration?
6. Spud's `h.condition` for melee crits looks like a bug (constant 1). Is the retail rule a health percentage? This needs one retail comparison before it goes into any formula table.
7. Is the `fArmorScalingFactor` 0.12 / `fMaxArmorRating` 80 pair correct for Skyrim SE? I could not verify it without a GMST dump, so the fallback values in [`combat.cpp:671-677`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/combat.cpp#L671-L677) are unverified either way.
8. Which hand does the retail engine consider for `GetEquippedItemType` when both hands hold different items? Spud's answer ([`combat.cpp:249-265`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/game/combat.cpp#L249-L265)) has three special cases and I did not verify it.

## Limits of this pass

- No tests exist in spud, so no row is `impl+tests`; every "impl" means "I read the code and it runs", not "it was verified against the game".
- I did not read `item_menus.cpp`, `crafting.cpp` beyond `improvement`, `alchemy.cpp`, `perks.cpp`, `caster.cpp`, `combat_ai.cpp`, `projectiles.cpp` or `magic.cpp`. Rows that depend on them say so or stay `unverified`.
- Numbers marked "unverified" in the vanilla-rules column come from memory of the retail rules, not from data in the spud repository. That repository contains no GMST dump, so a value like `fArmorScalingFactor` cannot be settled here.
