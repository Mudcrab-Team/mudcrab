## Architecture

Seven pieces: six in the runtime path, plus a headless harness. All synchronous and single-threaded.

1. **Importer** `ScriptCompiler` ([`src/importer/convert/script_import.cpp:118`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/importer/convert/script_import.cpp#L118) `add`, [`:308`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/importer/convert/script_import.cpp#L308) `add_attachments`, [`:451`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/importer/convert/script_import.cpp#L451) `finish`, [`:503`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/importer/convert/script_import.cpp#L503) `import_scripts`). Reads every `.pex` the load order can see plus the VMAD of each winning record, and writes one `<cache>/scripts/scripts.oss`.
2. **Data model** `oss::Scripts` ([`src/formats/oss.hpp:171-187`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/oss.hpp#L171-L187)): thirteen parallel tables (`SCRP`, `VARS`, `PROP`, `STAT`, `FUNC`, `SLOT`, `INST`, `OPER`, `ATCH`, `APRP`, `AVAL`, `FRAG`, `STRS`). Names are resolved at import; PEX debug tables are dropped ([`docs/formats/oss.md:44`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/formats/oss.md#L44)).
3. **VM** `script::VirtualMachine` ([`src/script/vm.hpp:227`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.hpp#L227)). Owns `Class`, `Object`, `Stack`, strings, ready list, three timer heaps and two update lists. Borrows `const oss::Scripts&` and a `Host&` ([`vm.hpp:362-364`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.hpp#L362-L364)).
4. **Host boundary** `Host` ([`vm.hpp:198-219`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.hpp#L198-L219)): `form_class`, `handle_class`, `reference_base`, `handle_text`, `in_menu_mode`, `game_days_passed`, `player_sleeping_or_waiting`, `log`. `GameHost` ([`src/script/natives.hpp:22-69`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/natives.hpp#L22-L69)) implements it over `forms::Database` and holds globals, form-list additions and world callbacks.

Engine binders run later from `App` startup ([`src/engine/app_items.cpp:553-558`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_items.cpp#L553-L558): game, character, actor, misc, presentation, reference, then `bind_world_natives` at [`app_world_natives.cpp:32`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_world_natives.cpp#L32)). Scheduler design (one thread, cooperative):

```
                     ┌──────────────────────── m_ready : deque<StackId> ─────────────┐
                     │  push: ready() — only if !queued (dedup)                     │
                     └───────────────▲──────────────────────────────────────────────┘
   new_stack (call_method / call_static / event / property_init / init_event)
        │ post_call ──► messages ring (1024) ──► overflow
        ▼
   dispatch(): swap(m_ready) ── for each stack ── run_slice(stack)
        │                                          │ up to k_slice = 100 instructions
        │                                          ├─ do_call → perform_call(from_tasklet=true)
        │                                          │     ├ inline script frame (Flow::entered)
        │                                          │     ├ native bound → run now
        │                                          │     └ latent → waiting_latent, unlock, native
        │                                          │           calls vm.wait() or later
        │                                          │           return_from_latent(stack, v)
        │                                          ├─ ret / end of code → return_from_frame
        │                                          └─ other suspend → Flow::left (suspend(state))
        └─ slices end → ready(s) (re-queue at tail)

   suspended sides [2 buffers] ── suspended_stage() retries: waiting_memory|waiting_call,
                                  waiting_return(no_pop) once the object is initialised/unlocked
   waits[3] min-heaps (gameplay ms | real ms | game ms=days*1000) ── fire_timers()
   updates[] gameplay ms + OnUpdate ; game_updates[] game ms + OnUpdateGameTime
   objects: lock_owner, properties_left, constructed, initialised, valid, reset_pending
```

Key ordering constraints visible in the code:

- A call on an object that is not `constructed`, or not `initialised` (and not the object being initialised), suspends as `waiting_call` ([`vm.cpp:782-784`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L782-L784)); the caller must not observe a half-initialised script.
- `apply_properties` holds one extra property count so `OnInit` cannot run before the last setter returns ([`vm.cpp:1749`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1749), `1800-1804`).
- A latent native releases the object lock before it runs ([`vm.cpp:885`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L885)), so a second stack can enter the same object while the first waits.
- `Return`/frame pop re-acquires the caller's lock and can re-suspend ([`vm.cpp:914-919`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L914-L919)).
- Timers fire in the update, before `dispatch()`, so a woken stack runs in the same frame.
- `OnUpdateGameTime` is skipped while the player sleeps or waits ([`vm.cpp:1454`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1454)).
- `Reset` is deferred to the next `update` and skipped while the object is locked ([`vm.cpp:1469-1482`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1469-L1482)).
- Save/load assumes a slice boundary: "Slices end on instruction boundaries, so a stack is always in a state the next dispatch can pick up" ([`vm_save.cpp:1-5`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm_save.cpp#L1-L5)).

**What is *not* supported, and how it fails.** The count of declared-but-unanswered natives is cache-specific and **unverified**: it depends on which scripts the installed game ships. The mechanism is exact, though:

- `stand_ins()` ([`natives.cpp:484-497`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/natives.cpp#L484-L497)) walks every `Script`/`State`/`Function` in `scripts.oss`, and for each `function_native` without a binding calls `declare()`.
- `declare()` ([`natives.cpp:503-519`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/natives.cpp#L503-L519)) binds a lambda that logs `warning: native Class.Name waits for a game system` **once**, then returns the declared return type's default; if the native is in the latent table it sets `started = false`, and the VM logs `Latent function X did not successfully start - aborting call` and resumes the stack with None ([`vm.cpp:888-891`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L888-L891)).
- So an unanswered call is a silent default after one log line. It is never a hard script error, and the script continues.
- `stub_natives()` ([`vm.cpp:256-278`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L256-L278)) can rank stubs by call-site count, but nothing calls it: the diagnostic exists and its caller is absent (`partial`). The reporting that *does* reach an operator is the warn-once log line, which the harness aggregates: `skytool script quests` counts warnings by first line and prints the top 25 ([`apps/skytool/cmd_script.cpp:190-197`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/apps/skytool/cmd_script.cpp#L190-L197)).

### Issue context and what it changes

- **#399 item 11 ("Papyrus differential contracts")** already asks for the right first step: synthetic PEX with a property setter, an inherited call, a nested latent wait and a later event, compared with an explicit fake clock and instruction bound. Spud's VM is a working reference for exactly that trace shape ([`vm.cpp:881-951`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L881-L951), `1705-1804`), but its scheduler is single-threaded and simplified, so use it as a *second opinion*, not the oracle. #399 also says "keep one VM/scheduler"; that rules out importing a second VM and supports implementing the scheduler in the engine over the existing Luau output.
- **#298 (consumed-data inventory)** applies directly: the converter writes `scripts`, `script_properties` and `script_property_values` (`db-schema.md:786-815`), and no engine reader exists (`rg` finds none). Under #298's states, VMAD data is `preserved` and `query-dependent`, not `runtime-projected`; that is a precise, checkable entry for the inventory, and the proposed inventory generator would have caught it.
- A separate Rust Havok library is under licence discussion; see issue #572.
- No open PR or issue read for this report tracks the Papyrus runtime itself. The only code is the converter emitter, the shared Luau runtime module and the two-test engine module.

### What in spud's design transfers, and what does not

**Transfers (idea-level; spud is MIT, Mudcrab GPL-3.0 — reimplement, do not copy text):**

1. **The attachment model and its application order.** `Attachment{form_id, alias, script, status, properties}` plus `AttachedProperty{array, values}` is the same data Mudcrab already stores. The portable rules are: skip `status == 3`; apply the base record's values before the reference's own; a read-only property logs and is skipped; hold `OnInit` until the last setter has returned ([`vm.cpp:1731-1804`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1731-L1804)). That solves a Mudcrab problem before it appears: quest aliases are called the frame they fill.
2. **An explicit "object is not ready yet" gate.** `constructed` / `initialised` / `valid` / `reset_pending` and "a call on a non-initialised object suspends" ([`vm.cpp:782-784`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L782-L784)) is cheaper than making every caller defensive. In Luau it becomes three booleans on the instance table plus a host-side wait list.
3. **A per-call latent token instead of a blocking call.** `NativeCall.started`, `Stack::in_latent`, `return_from_latent(stack, value)` ([`vm.cpp:881-951`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L881-L951)) is the contract Mudcrab's `Utility.Wait`, `Message.Show`, `Enable`, `MoveTo` and `PlayAnimationAndWait` all need. It also answers the "nested latent in a deep stack" case that #399 item 11 asks to test: the token identifies the *stack*, not the frame, and the return is stored at the call site on resume.
4. **Three clock domains with explicit pause rules.** gameplay ms (pauses in menu mode), real ms, game time in `days × 1000` ([`vm.cpp:272`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L272), [`:1366-1418`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1366-L1418)). Mudcrab has a calendar/converted data path; this is the smallest correct model and its constants are testable (`WaitGameTime(h) = (days + h/24)×1000`).
5. **Bounded slices and a two-buffer suspend list.** 100 instructions per stack per dispatch, ready-queue dedup, message ring 1024 + overflow, suspend ring 128 + overflow, and a "budget split 45 % messages / 40 % retries" rule ([`vm.cpp:18-24`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L18-L24), [`:1485-1561`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1485-L1561)). Any Luau scheduler needs the same shape or a single script can starve a frame.
6. **A stub inventory ranked by call sites** ([`vm.cpp:256-278`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L256-L278)). Mudcrab's runtime asserts today, which fails the script; spud's warn-once-then-default keeps a quest moving. Borrow the ranking, since it turns "what do we implement next" into a measured list. Keep Mudcrab's stricter CI mode separately.
7. **Constants worth lifting verbatim for parity tests:** array size 1…128, string 1023, float tolerance 1e-4, minimum update 33 ms, max wait 86 400 000 ms, `iMaxAllocatedMemoryBytes` 153 600, `fUpdateBudgetMS` 1.2 ([`vm.cpp:18-25`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L18-L25), [`vm.hpp:221-225`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.hpp#L221-L225), [`vm.cpp:1230-1242`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1230-L1242), `1410`).

**Does not transfer:**

1. **The `.oss` bytecode and the C++ interpreter.** Mudcrab's design is `.pex` → Luau at conversion time (`docs/roadmap/01-asset-pipeline.md:31`, §1.5 `:76-79`). A second intermediate format and a second VM contradict #399 ("reject whole-world/VM/… transplants", "keep one VM/scheduler"). Take the *schema* lesson (`Function.flags`, `return_type`, `parameter_count`), not the container.
2. **`mark_stub` / `bind_native` late-binding mechanics.** Luau's equivalent is a metatable `__index` on the native registry that logs once and returns a typed default. The policy transfers; the C++ map + `Function` patching does not.
3. **Serial tasklets with FIFO re-queue.** spud admits this changes observable ordering ([`vm.hpp:3-6`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.hpp#L3-L6)). Mudcrab should define ordering at the host scheduler (deterministic fixed step) rather than inherit a queue order that exists only because a thread was removed.
4. **Estimated frame memory accounting** (`frame_bytes`, 16 bytes/slot + 4). `mlua` gives `set_memory_limit`; use that, and keep 153 600 only as a parity *test* value, not a runtime allocator.
5. **Dropping PEX debug tables.** spud prints `Line ?` forever ([`vm.cpp:1889`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1889)) because the importer discards them ([`script_import.cpp:137-144`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/importer/convert/script_import.cpp#L137-L144)). Mudcrab's converter currently drops them too, but the `.pex` debug table is optional and small; keeping file/line would make every future script bug report cheaper. Do not copy the liberty.
6. **The whole-object lock.** It exists because tasklets could interleave. With one scheduler and one stack per object, it reduces to the readiness gate (item 2 above). Do not port `lock_owner`/`waiting_call` retry loops.

## Port notes

### Pitfalls and hidden coupling

1. **A native class exists only if a script of that name is in the load order.** `form_value(id, "Actor")` and `object_for()` call `find_class(name)` ([`vm.cpp:1637-1645`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1637-L1645), [`:1628-1633`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1628-L1633)), which resolves only `oss::Scripts.SCRP`. A load order that does not ship `Actor.pex` makes every `Actor` value None and every actor script unbound ([`vm.cpp:1690-1698`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1690-L1698)). Mudcrab's converted data has the same shape (`Script.__name`, `register_class`), so the runtime must synthesise the engine classes (`Form`, `Actor`, `ObjectReference`, `Alias`, …) rather than depend on authored scripts.
2. **Papyrus truthiness is not Luau truthiness.** `is_true` ([`vm.cpp:332-343`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L332-L343)) makes `0`, `0.0`, `""` and empty arrays false. The converter's `jmpt`/`jmpf` currently emit `if <value>` (`script.rs:772-785`), where Luau treats `0` as true and only `nil`/`false` as false. Every `If count > 0` style branch on an integer is a candidate mismatch. Fix before any quest runs.
3. **Object identity is by handle as well as pointer.** `compare()` returns 0 for two distinct `Object`s with the same handle ([`vm.cpp:446-453`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L446-L453)). One reference can hold several objects (a placed ref's own script + its base's), and they must compare equal to the form-id value the script passed in. A Luau port needs the same rule: compare `__formId` first, object identity second.
4. **Nested assignment keeps the value; a plain assignment resets to None.** `store_into(..., assign=false)` logs an error and stores the value; `assign=true` warns and stores the type's default ([`vm.cpp:556-572`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L556-L572)). Getting this backwards silently zeroes variables instead of failing loudly.
5. **Property initialisation has three paths** ([`vm.cpp:1754-1796`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1754-L1796)): auto → direct variable write; full with setter → a `property_init` stack; full read-only → warning + skip. The base record's values run before the reference's, and the extra held count is what stops `OnInit` running early. A Mudcrab implementation that calls setters synchronously will run `OnInit` too early in exactly the cases that matter (aliases filling in).
6. **`array_get` casts, `array_create` fills.** `array_create` writes a default element into every slot ([`vm.cpp:1250`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1250)); Mudcrab's `table.create(n)` only reserves capacity, so every slot is `nil` and `#arr` is 0. If you keep `table.create`, `Array_Length` and `Array_Get` need explicit fixes. `array_get` also casts on read ([`vm.cpp:1288`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1288)), which I believe vanilla does not (`unverified`); pick a rule and test it.
7. **A latent native releases the object lock before it runs** ([`vm.cpp:885`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L885)). Any native that expects exclusive access to the script object after starting is wrong. The same applies to Mudcrab if a job yields.
8. **A 1 s frame advances the gameplay clock 166 ms** ([`vm.cpp:1410`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1410)). Long hitches under-advance script timers and `Wait`. Decide whether to copy the clamp or use real elapsed time; do not leave it implicit.
9. **`m_game_clock` is recomputed every update from `days_passed`** ([`vm.cpp:1417`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1417)) but is also saved ([`vm_save.cpp:153`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm_save.cpp#L153)). Any `WaitGameTime` value that crosses a save depends on the host clock, not on the saved number.
10. **Timers fire before dispatch, and `OnUpdateGameTime` is skipped while sleeping/waiting** ([`vm.cpp:1454-1456`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1454-L1456)). Order matters for a "wait 0.1 s then notify" fixture.
11. **Re-registering an update keeps the single-shot flag** ([`vm.cpp:1379-1386`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1379-L1386), comment at `3.4`): `RegisterForSingleUpdate(0.5)` then `RegisterForUpdate(0.1)` leaves a single-shot registration. Copy or fix deliberately.
12. **Events never run re-entrantly.** `send_event` enqueues stacks via `post_call`; the event body executes on a later dispatch ([`vm.cpp:1841-1878`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1841-L1878)). A script that sends an event to itself will not observe it inside the same function.
13. **A base-type mismatch silently skips the script** (error log only) — for example a `Quest` script in a `REFR` VMAD. Do not "fix" this by attaching anyway; it hides real data errors ([`vm.cpp:1690-1698`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.cpp#L1690-L1698)).
14. **Fragments are keyed by `(form, kind, index, entry)` and only one function name each** ([`oss.hpp:160-169`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/oss.hpp#L160-L169), [`script_import.cpp:386-448`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/importer/convert/script_import.cpp#L386-L448)). Import coverage is exactly QUST/INFO/PACK/SCEN/PERK; anything else in a VMAD fragments section is dropped without a warning.

### Minimal vertical slice that proves the subsystem

Fixture: one synthetic `.pex` (or `QF_` script) with

- `Scriptname PvmSlice extends Quest`
- `Actor Property Target auto` and `int Property Counter auto`
- `Event OnInit()` → `Debug.Notification("init")`, `RegisterForUpdate(0.1)`, `GoToState("Active")`
- `State Active` with `Event OnUpdate()` → `Counter += 1`; if `Counter == 2` → `Utility.Wait(0.5)`, `Target.Enable()`, `Counter = 0`
- an empty-state `OnUpdate` that notifies `"fallback"` (to prove state precedence)

Plus a synthetic VMAD for the quest form: `Counter = 7`, `Target = 0x0001A2B3` (a REFR with an enable-parent, to also prove the refusal path).

Exact check, headless, fake clock, 33 ms per update:

1. `Notification("init")` appears once, before any `OnUpdate`.
2. `Counter` reads 7 in the first `OnUpdate` (VMAD applied before `OnInit`).
3. The state change makes `Active::OnUpdate` run, not the empty-state version.
4. `Wait(0.5)` suspends that stack only; other registered scripts keep updating during the wait; the stack resumes exactly once with None.
5. `Target.Enable()` on an enable-parent reference logs the refusal and leaves `IsDisabled` unchanged.
6. Total instruction count per dispatch stays ≤ 100 per stack; the whole scene is deterministic across two runs.

Mudcrab equivalent: load the emitted `.luau` with `load_runtime`, register one test native per call in the trace, and compare an ordered event log; the same fixture must produce the same log through spud's VM. That is exactly the differential contract #399 item 11 asks for, with spud as a second opinion and not as the oracle of record (spud is single-threaded and has documented simplifications).

## Test ideas

Deterministic, headless, no game launch. The cheapest home for cases 1-11 is spud's own harness ([`apps/skytool/cmd_script.cpp:44-104`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/apps/skytool/cmd_script.cpp#L44-L104)): it already fixes the clock at 60 fps, accepts a synthetic `.pex` with `--add`, and can save/reload mid-run with `--save-at`. Adding assertions to its stdout is a small change; Mudcrab should build the same runner for its emitted `.luau`.

1. **Opcode conformance, 36 cases.** One synthetic PEX per opcode, executed against a trace native; assert value, destination write and error text. Include the four error paths: divide by zero, `INT_MIN / -1`, bad cast, out-of-range array index.
2. **Truthiness matrix.** `If 0`, `If 0.0`, `If ""`, `If None`, `If emptyArray`, `If 0.00001`, `If 0.001`. Expected: false, false, false, false, false, false, true. Catches port-note item 2 immediately.
3. **Compare matrix.** int/int, float tolerance at ±1e-4, string case pairs (`"Iron Sword"` vs `"iron sword"`), `None == None`, object vs form-id value on the same handle, arrays of different length.
4. **Property application order.** Base VMAD + reference VMAD on the same script: assert the reference's value wins, that a read-only property is skipped with one warning, and that `OnInit` observes the final value.
5. **Setter re-entrancy.** Property setter calls `Other.GetValue()`; assert the other object's `OnInit` has already run or the call suspends, never observes a half-initialised object (port-note item 5).
6. **Nested latent.** A → B() → `Wait(1.0)` → return to A. Assert A does not resume before B, the return value lands at A's call site, and one timer entry exists.
7. **Latent that fails to start.** A stub latent returns `started = false`; assert one error, an immediate None, and that the stack continues (this is the missing-native path).
8. **State precedence.** State override present/absent × parent script present/absent (four cases), plus `GoToState("")` returning to the empty state.
9. **Array semantics.** Create 3, read each slot (expect the element default, not nil), set to None, `Length` after the write, `Find` from 0 and from 2, `RFind` with start=-1, index -1 and index == length.
10. **Update scheduling.** `RegisterForUpdate(0.01)` clamps to 33 ms; `RegisterForSingleUpdate` fires once; `RegisterForUpdate` after a single-shot keeps the single-shot flag (documents port-note item 11); `OnUpdateGameTime` does not fire while `player_sleeping_or_waiting` is true.
11. **Save round-trip.** A stack suspended in `Wait`, one in `RegisterForSingleUpdate`, one with a pending property setter; save, load into a fresh VM, advance the clock, assert all three resume at the right time and the setter still completes. Then delete the function from the `.oss` and assert the documented drop (Mudcrab should instead fail loudly).
12. **Stub audit as data.** Assert `stub_natives()` output for a synthetic script set counts call sites and sorts descending; use the same shape for a Mudcrab CI report of unimplemented natives.
13. **Interrupt budget.** An infinite loop is killed with the budget error and leaves the other scripts runnable (Mudcrab already has this test shape at `papyrus_runtime.rs:99-104`).

Fixtures to extract from vanilla data (read-only, converted once):

- `Actor.pex`, `ObjectReference.pex`, `Form.pex`, `Quest.pex`, `Utility.pex`, `Debug.pex` — the class/native surface, and the only way to obtain real native signatures and return types.
- One `QF_*` quest script with a state block and a stage fragment; `MQ101`/`MQ102` are the usual smoke fixtures.
- One `REFR` VMAD with an auto object property bound to another reference, and one with a read-only full property (to exercise the warning path).
- One `MGEF` script (`OnEffectStart`/`OnEffectFinish`) and one `PERK` with an entry-point fragment.
- One `FLST` used as an inventory event filter.
- One `.pex` compiled with debug info, to decide whether Mudcrab keeps line numbers (spud does not).

## Open questions

1. **Runtime native count for a given install.** The stub count is cache-specific and unverified here. `stub_natives()` has no caller, but `skytool script quests` already histograms the warn-once "waits for a game system" lines and prints the top 25 ([`apps/skytool/cmd_script.cpp:190-197`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/apps/skytool/cmd_script.cpp#L190-L197)). Cheapest path: run that with `--frames` on a real cache and count distinct warning texts, or add a `--dump-natives` mode that prints bound vs declared per class.
2. **Whether a stripped load order breaks all natives** in practice (port-note item 1). Cheapest path: run the stat-only path with only `Quest.pex` present and check `Game.GetPlayer()`.
3. **`array_get` casting.** spud casts the element to the destination type; I believe the documented VM does not. `unverified`; settle with a two-line `.psc` fixture compiled in the CK (int property read into a float local).
4. **Base-vs-reference property precedence.** spud's comment claims the reference inherits its base's values "unless it says otherwise"; I could not verify against the game without a save-game experiment.
5. **The auto-property-without-variable null dereference** (`pvm-prop-nullcode`). The code path is clear but was not executed; a synthetic malformed `.pex` would settle it in one run.
6. **`HasLOS` for two NPCs** always returns false ([`actor_natives.cpp:245-255`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actor_natives.cpp#L245-L255)). Whether any shipped quest depends on it is unknown.
7. **`SendPlayerToJail`, `PathToReference`, `MoveToPackageLocation`** are marked latent but complete without the movement finishing ([`actor_natives.cpp:106-109`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actor_natives.cpp#L106-L109), [`:272-281`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/actor_natives.cpp#L272-L281), [`misc_natives.cpp:130-135`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/misc_natives.cpp#L130-L135)). Vanilla semantics here are `unverified`; a script that relies on the actor having arrived will misbehave.
8. **Which natives are latent in vanilla.** spud's table is hand-written; a wrong flag makes a native synchronous (harmless) or latent (hangs a stack). Cheapest check: compare the table against `*.psc` `native` declarations plus the known-latent list in the CK wiki; a mismatch is a one-line bug.
