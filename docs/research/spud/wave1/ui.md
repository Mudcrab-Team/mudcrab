Nothing was built or run. See the [README](../README.md) for evidence levels and the licence note.
> **Topic:** Spud `src/ui`: converted Skyrim interface movies, an AS2 interpreter, menus, HUD and input routing.

## Summary

- `src/ui` has 54 files and 29,007 lines, measured with `find` and `wc -l` on 2026-11-13.
- The area plays Skyrim SE's own interface movies, converted from the user's Interface BSA into `.osu` cache files.
- It is neither ImGui nor a native retained-mode widget toolkit. It is a custom Flash 8 / ActionScript 2 and Scaleform GFx 3.x-compatible runtime.
- Menu logic is native C++ `Menu` subclasses and `UiHost` delegates. The movie scripts and artwork remain game-provided.
- Maturity is broad and substantial at source level. Runtime fidelity is not independently established by this read-only audit.
- Important features: Flash movie VM and display tree; original menu movies; per-menu gameplay callbacks; layered movie renderer; keyboard, mouse and partial gamepad routing.
- Important features: 3D item/book/lock previews, loading scene selection, local map target, and a stat-screen starfield.
- Major liberties: GFx/AS2 is reimplemented as a compatibility subset; save and some game services are delegated to spud; a custom Graphics settings page changes the stock Journal.
- Major gaps: gamepad stick navigation is explicitly limited; some menu callbacks use empty captured defaults; some vanilla console aliases are unavailable.
- Verdict: the source supports strong visual reuse of vanilla menus. Exact behavioural parity requires runtime comparison against Skyrim captures and input traces.

## Data and file formats

- `.osu` is spud's converted UI movie format. Import reads interface SWF movies and emits converted geometry, glyphs, bitmaps and scripts. See [`docs/UI.md:1-15`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/UI.md#L1-L15) and `docs/formats/osu.md`.
- Source assets include `Skyrim - Interface.bsa`, `fonts_<language>.swf`, `fontconfig.txt`, `translate_<language>.txt`, `controlmap.txt`, `keyboard_english.txt`, `gamepad.txt`, and game string settings. See [`docs/UI.md:13-15`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/UI.md#L13-L15), [`:44-49`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/UI.md#L44-L49), [`:89-94`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/UI.md#L89-L94).
- Book images are converted to RGBA8 DDS textures. Loading screen scene/model/camera data uses `.osl`. See [`docs/UI.md:13-15`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/UI.md#L13-L15), [`:44-49`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/UI.md#L44-L49) and `docs/formats/osl.md`.
- UI state and movie dumps can be JSON; `settings.ini` stores interactive settings in `%LOCALAPPDATA%\\spud`. See [`docs/UI.md:81-87`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/UI.md#L81-L87), [`:114-145`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/UI.md#L114-L145).
- The UI reads render target `Local_Map` and book page render targets; it also produces GPU draw lists and screenshots. See [`docs/UI.md:44-49`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/UI.md#L44-L49), [`:114-151`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/UI.md#L114-L151).

## Cross-area dependencies

- Importer supplies `.osu` movies, localized fonts, translations, control map, GMST strings, loading scene resources, and book textures.
- `src/ui/player` supplies AS2 execution, text, hit testing, display tree, movie library and draw-list generation to menu code and the renderer.
- `src/ui/movie_renderer` depends on `render::Overlay`, shaders and texture upload. UI 3D scenes use the common mesh/model/effect paths.
- `UiHost`/`src/engine/app_menus.cpp` supplies game actions, player and calendar data, settings, save operations, console commands and scene/world data.
- World map depends on engine local-map rendering; loading and Mist depend on engine backdrop; item, lock, book and starfield scenes feed the menu overlay.
- UI exposes `local_map_view`, menu state, focus, trace hooks, automation commands and draw output to engine/app and developer tooling.

## Liberties and deviations

1. **Visible to player — Graphics page changes vanilla Journal.** `JournalMenu::add_graphics_page` adds a fourth page and exposes spud-specific controls. Evidence: [`docs/UI.md:85-87`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/UI.md#L85-L87); `src/engine/graphics_settings.*`.
2. **Gameplay correctness — native callbacks are spud services.** Movies are original, but menu actions and data come from `UiHost` and engine code, not Bethesda's executable. This creates broad parity risk wherever actions, save state, character progression or world data differ. Evidence: `src/ui/menu.hpp`, `src/engine/app_menus.cpp`, menu-specific handlers.
3. **Gameplay correctness — movie runtime is a compatibility implementation.** Player and VM reproduce Flash 8 / AS2 and GFx behavior in-house. Unsupported or differently implemented semantics can change menu behavior. Evidence: [`src/ui/player/player.hpp:3-6`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/ui/player/player.hpp#L3-L6), `src/ui/player/vm.cpp`, `src/ui/player/builtins_display.cpp`.
4. **Gameplay correctness — controller coverage is incomplete.** Left stick becomes arrow-key repeat for menus; code comment says only Mist currently consumes both sticks and other menus do not read them. Evidence: [`src/ui/ui.cpp:1466-1505`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/ui/ui.cpp#L1466-L1505).
5. **Visible to player — selected console alias is missing.** `coc` cannot resolve exterior EditorIDs because importer does not provide them. Evidence: [`docs/UI.md:74-80`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/UI.md#L74-L80).
6. **Gameplay correctness — capture defaults can hide missing state.** Magic-related fallbacks include empty favorites and absent shout/model state. Evidence: [`src/ui/menus_magic.cpp:218-228`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/ui/menus_magic.cpp#L218-L228), [`:334-344`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/ui/menus_magic.cpp#L334-L344).
7. **Internal only — UI is tied to converted user assets and cache.** Movies are not shipped and must be imported from the user's game. This is a deliberate asset/provenance choice, not a visual deviation when conversion succeeds. Evidence: [`docs/UI.md:1-15`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/UI.md#L1-L15).

## Claims versus code

- `docs/UI.md` says the menus look and behave as the game. Code shows the original movies are played, but engine actions, data, and movie runtime are implemented by spud. Treat exact behavior as a claim until paired runtime tests establish it.
- The docs list all menu families and inspection tooling; corresponding class declarations/handlers exist in `menus.cpp`, `menus_items.cpp`, `menus_magic.cpp`, `menus_hud.cpp`, `menus_stats.cpp`, `menus_world.cpp`, `menus_loading.cpp`, and `menus_journal.cpp`.
- The docs explicitly qualify partial coverage for `coc`, Graphics options, and gamepad sticks. Source comments corroborate these limits.
- No clear UI feature found in code but absent from `docs/UI.md` during this bounded inspection. File-level exhaustive review was not performed.
- Docs mention replayable loading conditions, translation, font mapping and book image registration. This audit found corresponding code/documentation references but did not run the importer or runtime tools.

## Open questions

- Which AS2 opcodes, Scaleform extensions, filters and text APIs remain unsupported? Cheapest check: inspect movie-player error inventory, then run `skytool ui play --all` against the converted interface cache and categorize errors.
- How close are each menu's input, focus, animation and scene output to Skyrim? Cheapest check: compare same-state paired screenshots and scripted input traces, starting with inventory, Journal, map, lockpicking and loading.
- Which fallback paths occur in normal play versus test captures? Cheapest check: trace menu delegate calls during representative Skyrim-equivalent states and compare required fields with host outputs.
- Does controller support cover face buttons, triggers, remapping and menu-specific gestures beyond the documented left-stick path? Cheapest check: route a complete gamepad control-map sequence through each menu and compare to Skyrim.
- Does spud's map render and marker layout match Skyrim at the same world/camera state? Cheapest check: capture `ui localmap` plus paired in-game map screenshots.
