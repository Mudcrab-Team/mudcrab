## Summary

- The gameplay integration layer connects Skyrim forms and game systems to the player, actors, UI, world streaming, and save files.
- Scope size: 27,293 measured lines across 46 requested source/header files (wildcard app files plus named gameplay files).
- Maturity: broad implemented feature set; no tests were found in the inspected engine paths. Runtime parity remains unverified here.
- New-game flow starts character setup, loads the opening location, and starts configured intro quests through Papyrus.
- Saves persist game, Papyrus, quests, world simulation, actor state, destruction, map discovery, and clock state.
- Doors combine activation, portal geometry, cell/world travel, destination placement, and room visibility.
- Combat, dialogue, mounts/carts, item transactions, and journal/map UI are wired into game state and actors.
- Largest liberties: custom `.ost` save format instead of Skyrim save files; implementation-defined cart and dragon mount behavior; camera/combat/death paths are not demonstrated as vanilla-equivalent.
- License caveat: Spud is MIT and Mudcrab is GPL-3.0. Borrow techniques and ideas, not code.

## Data and file formats

- `.ost` is Spud's versioned save container. The app writes component sections for Game, Papyrus, quests, world simulation, destruction, local-map discovery, clock, and actor extensions ([`app_saves.cpp:218-340`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L218-L340); [`docs/formats/ost.md:1-14`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/formats/ost.md#L1-L14)).

## Cross-area dependencies

- `game`: owns combat, AI, inventory, quests, dialogue, crime, actor values, settings, and saved system state. App supplies world/presentation adapters.
- `forms` and importer outputs: provide records, links, scripts, voice types, doorway placement, destruction stages, and item data.
- `ui`: menu/movie callbacks call App hosts; journal and local map are UI source/render adapters.
- `actors`, `anim`, `audio`, `physics`, and `render`: provide actor skeleton/animation, sound, collision queries, cameras, and offscreen map output.
- `world_sim` and `Space`: provide worldspace/cell identity, markers, travel checks, streaming, roster placement, and quest-map targets.
- Exposes player-facing interactions through UI host callbacks, Papyrus native bindings, save hooks, and debug/automation commands.

## Liberties and deviations

1. **Spud-specific save format — affects gameplay correctness and compatibility.** It writes `.ost` component sections and plugin identity rather than Skyrim saves. Evidence: [`docs/formats/ost.md:1-14`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/formats/ost.md#L1-L14); [`app_saves.cpp:218-340`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/app_saves.cpp#L218-L340).
2. **Fast-travel time/arrival implementation — visible to a player.** Spud computes journey length/time and applies its own arrival lift and placement path. Exact vanilla formulas were not compared.
