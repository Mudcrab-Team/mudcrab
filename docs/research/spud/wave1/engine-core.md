> Written with an AI assistant; research notes, not checked line by line by a human. Read-only source review of [spud](https://github.com/chasmlol/spud) (MIT) at commit [`8c990420`](https://github.com/chasmlol/spud/commit/8c9904207a5c573a0193fb903fb5c433f127f102), 2026-11-13. Nothing was built or run. See the [README](../README.md) for evidence levels and the licence note.
> **Topic:** Spud `src/engine` core and `src/script`: camera, player motion, world presentation, settings, weather helpers, scripted commands and the Papyrus VM.

## Summary

- Spud's engine core drives frame-side camera, player motion, world presentation, settings, weather helpers, scripted commands, and Papyrus.
- Measured scope: 10,475 lines across the reviewed core files listed in the file inventory; 34 file paths counted.
- The full `src/engine` and `src/script` trees contain 49,277 lines measured with `wc -l`; this includes engine-app-owned files.
- Maturity is mixed: a substantial runnable implementation with detailed simulation and rendering integration, plus deliberate approximations and no evidence of unit coverage for most core features.
- Papyrus has a complete 36-opcode PEX instruction set in `oss::Op`; the VM dispatches these operations in `vm.cpp`.
- Papyrus serializes script execution through a ready queue, 100-instruction slices, object locks, latent timers, and event registrations.
- Runtime Papyrus native implementation count is not a fixed source count: the VM binds implemented functions and fills remaining declared functions with default-returning stubs.
- Runtime scripts-loaded count is cache-specific (`scripts/scripts.oss`) and was not measured because this read-only source review did not inspect or launch a game cache.
- Five notable features: deterministic fixed-step tours; gameplay/real/game-time latent scheduling; data-driven movement and stamina formulas; weather-driven precipitation depth occlusion; asynchronous grass-cell generation.
- Largest liberties: Papyrus tasklets run serially; calendar rollover advances at most one day/month boundary per call; movement and camera use reconstructed simplified rules rather than Skyrim's original engine.
- Other core areas include weather evaluation, interior lighting, water state, world simulation, space streaming, side-by-side comparison, test-cache generation, and world-map cameras.
- Worth borrowing: explicit fixed-step deterministic replay, per-feature modular systems, and first-class benchmark receipts with frame and GPU-pass measurements.
- License note: spud is MIT and Mudcrab is GPL-3.0; borrow ideas and techniques, not code.

## Data and file formats

- `.oss` is Spud's compiled Papyrus representation, stored at cache path `scripts/scripts.oss`. It keeps native PEX opcode numbering, typed slots, resolved operands, attachments, and fragments. Its spec is `docs/formats/oss.md`; code schema is [`src/formats/oss.hpp:1-24`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/formats/oss.hpp#L1-L24).
- `.osf` is the forms database consumed by `Papyrus` at `forms.osf`; the engine reads it through `forms::Database` ([`src/engine/papyrus.cpp:14-22`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/papyrus.cpp#L14-L22)).
- Papyrus save data is serialized by [`src/script/vm_save.cpp:1-398`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm_save.cpp#L1-L398); Papyrus exposes save/load integration in `src/engine/papyrus.hpp`.
- Game clock state is a binary sequence of seven floats and one midnight counter ([`src/engine/game_clock.cpp:52-66`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/game_clock.cpp#L52-L66)).
- Bench scenarios are line-based command files; results are JSON with CPU zones, GPU pass timings, digests, and runtime metadata ([`src/engine/bench.hpp:14-97`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/bench.hpp#L14-L97), [`src/engine/bench.cpp:1-283`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/bench.cpp#L1-L283)).
- Control requests and responses use JSON over a local socket ([`src/engine/control.cpp:1-319`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/control.cpp#L1-L319)).
- User settings persist in the application's settings file through `UserSettings`; exact filename is selected by app integration.
- Grass instances use a 32-byte packed runtime record ([`src/engine/grass.hpp:18-22`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/grass.hpp#L18-L22)).

## Cross-area dependencies

- Engine core consumes renderer types and renderer services for views, offscreen targets, GPU instances, water frames, weather environments, and performance pass timings.
- It consumes `formats::oss`, `.osf` forms, world cache records, Skyrim rules, and converted assets. The importer creates `.oss`; Papyrus does not parse Bethesda PEX directly.
- `Papyrus` depends on `GameClock`, `forms::Database`, `game::Conditions`, `QuestWorld`, and `QuestSystem`; native bindings call game, UI and app-host services.
- Movement depends on rules, world collision/terrain/water queries and player state. Camera collision is injected through a sphere-cast callback.
- Grass depends on world cells, renderer buffers and background-thread scheduling. Precipitation occlusion depends on space draw collection and renderer depth targets.
- Bench and command scripts expose scenario execution to app integration; they are not autonomous gameplay systems.
- Core exposes frame state, camera and movement helpers, Papyrus call/update hooks, weather/water frames, settings, and benchmark receipts to app and renderer layers.

## Liberties and deviations

1. **Papyrus tasklet serialization — gameplay correctness / timing.** VM comment states one thread runs everything and tasklets become a serial ready-list pass ([`src/script/vm.hpp:3-6`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/vm.hpp#L3-L6)). This can change ordering and timing compared with concurrent tasklets.
2. **Movement reconstruction — visible to player and gameplay correctness.** `movement::Settings` documents values that differ from Skyrim.esm values, including water knockdown and minimum jump-fall velocity ([`src/engine/movement.hpp:46-48`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/movement.hpp#L46-L48)). Spud integrates its own motion path rather than using Skyrim's physics engine.
3. **Calendar large-step behavior — gameplay correctness.** `GameClock::pass_hours` loops day increments but rolls month once, and only for one midnight event ([`src/engine/game_clock.cpp:24-48`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/game_clock.cpp#L24-L48)). A large step can produce a non-vanilla date.
4. **Precipitation occlusion — visible to player.** One strongest precipitation state selects a custom 512² projection volume ([`src/engine/precip_occlusion.cpp:10-69`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/precip_occlusion.cpp#L10-L69)); roof coverage can differ from Skyrim.
5. **Papyrus missing natives — gameplay correctness.** Unbound declared natives become warning/default-return stubs ([`src/script/natives.cpp:480-520`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/script/natives.cpp#L480-L520)), so scripts can continue with incomplete effects.
6. **Grass generation — visible to player.** Cell-based custom placement and asynchronous generation replace the original grass cache/generation path ([`src/engine/grass.cpp:1-589`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/grass.cpp#L1-L589)).
7. **Benchmark and control APIs — internal only.** Deterministic tours, JSON benchmark results and remote control are Spud-added tooling ([`src/engine/bench.hpp:14-97`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/bench.hpp#L14-L97); [`src/engine/control.cpp:1-319`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/control.cpp#L1-L319)).
8. **Main-menu backdrop — visible to player.** A specialized renderer scene uses fixed captured constants ([`src/engine/backdrop.cpp:20-38`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/engine/backdrop.cpp#L20-L38)).
