# Importer: spud conversion pipeline

> Written with an AI assistant; research notes, not checked line by line by a human. Read-only source review of [spud](https://github.com/chasmlol/spud) (MIT) at commit [`8c990420`](https://github.com/chasmlol/spud/commit/8c9904207a5c573a0193fb903fb5c433f127f102), 2026-11-13. Nothing was built or run. See the [README](../README.md) for evidence levels and the licence note.
> **Topic:** Spud `src/importer` and `apps/skytool`: how a Skyrim install becomes runtime caches.

## Summary
- Spud turns a Skyrim install and its active load order into a runtime cache of compact native files.
- Measured scope: 107 files and 35,689 lines across `src/importer` and `apps/skytool`.
- Maturity: broad implemented conversion pipeline; no importer test suite was found in the inspected tree.
- The top-level pipeline covers forms, rules, actors, scripts, world spaces, meshes, textures, UI, audio, and far views.
- It reads plugin records, loose files, BSA archives, NIFs, DDS textures, audio, Papyrus bytecode, and HKX animation data.
- It emits Spud-specific binary containers such as OSW, OSM, OSF, OSA, OSD, OSB, OSK, OSN, OSP, OSH, and OSS.
- Meshes and textures are reusable across imports when source hashes and converter versions match.
- Per-plugin form compilation also reuses cached units when plugin, strings, language, and schema inputs match.
- Far views bake terrain maps, tree impostors, and region proxies from the converted cache.
- Largest liberties: unsupported references are removed from exported worlds; audio/DDS can be copied unchanged; far trees and proxies are baked approximations.
- Important gaps: navmesh conversion is not visible in the importer; grass is represented as world metadata but no grass mesh extraction stage was established.
- License caveat: Spud is MIT and Mudcrab is GPL-3.0, so borrow techniques and designs rather than code.

## Cross-area dependencies

- `legacy::Install`, `DataSource`, `EsmDatabase`, NIF/BSA readers and strings handling provide the source layer.
- `records` owns the schema, codecs, plugin-unit compiler, fixups and final OSF link output.
- `convert/world_import` consumes plugin records and NIF-derived attach/animation metadata; it exposes source mesh and texture dependencies.
- Mesh conversion returns render geometry, collision, effects and discovered texture paths. The pipeline uses these results to decide which world refs survive.
- `far` reads completed OSW worlds, converted OSM meshes and source textures. The import pipeline calls it after writing cache outputs.
- `skytool` exposes importer controls; its `--game`, `--mo2`, `--profile`, and `--cache` globals are resolved in `apps/skytool/main.cpp`.

## Tests, tooling and gates

- `skytool import --help` documents world/interior filtering, thread count, force, audio-only, actors-only, doors-only and rules-only options.
- `skytool far --world <edid>` creates far views from an existing cache.
- `ImportSummary` reports missing/failed meshes and textures, dropped refs, reused assets, form units and audio failures.
- `cmd_import` returns status 2 when mesh or audio failures are nonzero.
- No `tests/` directory or importer-specific test registration was found in the inspected source tree. This does not prove that no external/manual tests exist.

## Liberties and deviations

1. **Gameplay correctness, high:** references to missing, failed or empty render meshes are removed from OSW. Vanilla keeps those records and may resolve them later through other assets. Evidence: [`pipeline.cpp:1128-1155`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/importer/pipeline.cpp#L1128-L1155), `drop_meshes` call; summary counts `refs_dropped`.
2. **Visible to a player, high:** far tree impostors are rendered from multiple angles instead of using the game's authored LOD asset path. Evidence: [`far/far_trees.cpp:1-2`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/importer/far/far_trees.cpp#L1-L2), [`:174`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/importer/far/far_trees.cpp#L174); per-cell placements at `326-349`.
3. **Visible to a player, medium:** region proxies remove glow, environment-map and tree-animation material flags. Evidence: [`far/far_proxies.cpp:55`](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/src/importer/far/far_proxies.cpp#L55).
4. **Internal / visual approximation, medium:** far terrain maps and proxies are generated from converted content rather than preserving all authored LOD data. ## Claims versus code

- `cmd_import --help` says unchanged inputs are not converted again. This is supported for cached mesh/texture assets and forms units. Small rules outputs, audio records, worlds and atmosphere use unconditional or write-if-changed paths instead of a universal importer cache.
- The pipeline header says it makes a self-contained cache of worlds, meshes and textures. The code also writes forms, actors, scripts, audio, UI, atmosphere, collision, effects, rules and far-view data.
- Far CLI help says it generates land maps, impostors and proxies. Code confirms distinct `bake_land`, `bake_trees` and `bake_proxies` stages.
- No broader docs claim about navmesh import was found in the inspected importer-specific code; the input-output coverage remains an open question.
