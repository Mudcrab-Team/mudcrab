## Summary

- Meta covers project intent, build setup, automation, quality gates, performance measurement, working rules, and history.
- The checkout contains 679 tracked and untracked visible files by `rg --files`; the meta document set measured 3,817 lines across selected docs, scripts, and tools.
- Spud is an early but unusually broad Skyrim SE engine prototype. The roadmap says most systems have a working first version with rough edges.
- The most notable practices are a single shared command language, deterministic headless control, explicit performance budgets, an image-history audit, and a machine-wide work gate.
- README claims are partly supported: the tree has no TAA implementation, and runtime APIs consume Spud formats. Generic DDS and WAV remain native generic inputs.
- The docs distinguish implemented scope from next and later work, while several docs describe intended behavior more broadly than automated coverage proves.
- The five largest meta features are headless scripted sessions, TCP live control, image history checks, exclusive performance runs, and the transparent development rules.
- Three major deviations are deliberate: generated LOD replaces Bethesda LOD, cities merge into Tamriel, and interiors stream through portals without loading screens.
- The code also explicitly chooses Jolt rather than Havok. This changes physics results by design.
- History shows 53 commits from November 6–7, all attributed to chasmlol, including dense performance and gameplay changes.
- The checked-in project license is MIT. The generated SADIE II HRTF data has a separate Apache 2.0 notice. Dependency licenses are not recorded in the vcpkg manifest.
- This is a source and documentation audit. No build, engine run, or test command was executed.

## Data and file formats

This area does not define Spud runtime formats. The formats report covers `docs/formats/`. Meta tooling reads and writes these supporting artifacts:

- `.bench` line-based scenario files drive the same engine command language described in `docs/AUTOMATION.md`.
- Performance output is JSON, with per-frame CPU/GPU timing and aggregate statistics. Baselines and budgets are JSON under `tools/perf/`.
- Agent control uses newline-delimited JSON over TCP on 127.0.0.1. Commands can return inline JSON with a path of `-`.
- Image audit writes screenshots and difference images as PNG. It compares pixel data with an explicit threshold.
- Cleanup and gate state are local machine files under Local AppData by default. The gate broker uses a Windows named pipe.
- Build presets use CMake JSON and vcpkg manifest JSON. Launch and tool wrappers are Windows batch files.
- `tools/hrtf/build_hrtf.py` produces embedded data from SADIE II. The repo includes the dataset license text and README exception.

## Cross-area dependencies

- Build targets connect core, formats, game, importer, script, fx, animation, UI player, and optional engine systems in `src/CMakeLists.txt`.
- `skytool` links importer, script, game, UI player, and fx. `spud` links the engine library.
- Gate wraps build, import, audit, perf, and launch commands. Perf and audit launch the engine in headless mode and depend on imported user game data.
- Automation commands expose systems owned by engine, game, UI, script, physics, audio, and rendering areas.
- The architecture claims Skyrim-specific format parsing stays in importer. Generic DDS and WAV are kept. This is supported by visible format comments and docs, but this meta review did not inspect every runtime call path.
- External dependencies listed in vcpkg are GLM, Jolt, Vorbis, LZ4, meshoptimizer, zlib, SDL3, stb, VMA, ImGui, and libtess2. The in-tree manifest does not include per-package license identifiers.

## Tests, tooling and gates

No tests or builds were run for this report. Static inventory found no CTest setup, separate tests directory, or CI workflow. It found eight scenario files and one tour, plus four fixed image-audit poses. These are inventory counts, not passing test counts.

- Build: `scripts\build.cmd release` configures once and builds through a shared gate pass.
- Import and run: `scripts\skytool.cmd import`, `scripts\spud.cmd --headless --run script.osc`.
- Gate: `scripts\gate.cmd status`; shared work permits concurrent non-build jobs but serializes builds; exclusive perf waits for shared work and checks for outside activity.
- Audit: `scripts\audit.cmd` runs static resource/temporal checks and optional headless image-history checks. `--static-only` avoids GPU checks.
- Performance: `scripts\perf.cmd` runs quick scenarios once. `--full` uses repeated runs and median; `--windowed` includes presentation and pacing.
- UI: `docs/UI.md` describes headless movie playback and a UI test suite. The exact suite invocation is malformed in `docs/AUTOMATION.md`, so its invocation and coverage need confirmation.
- Cleanup: gate may invoke `tools/clean/clean.py` when free space is low. The cleaner defaults to report-only behavior; deletion requires apply.

Performance checks compare CPU/GPU mean and percentiles, jitter, maximum, hitch counts, startup, streaming and memory. Regression failures require both a 10% relative change and 0.1 ms minimum delta. Budgets are specific to known hardware; unknown machines receive baseline regression checks only. The checked-in 5090 budget is 600 fps mean and 480 fps 1% low as documented, with corresponding frame-time caps.

## Liberties and deviations

1. **Generated LOD replaces source-game LOD. Severity: visible to a player.** Vision states original LOD files are never used and generated levels come from full-detail data. That changes distant views by design. Evidence: [docs/VISION.md:26-31](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/VISION.md#L26-L31); [docs/ARCHITECTURE.md:106-134](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/ARCHITECTURE.md#L106-L134).
2. **Cities merge into Tamriel. Severity: affects gameplay correctness.** Import merges city child worldspaces into the parent and uses region tags to preserve logical identity. This differs from vanilla's separate worldspaces while preserving some identity queries. Evidence: [docs/ARCHITECTURE.md:93-105](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/ARCHITECTURE.md#L93-L105).
3. **Interiors stream through portals with no loading screens. Severity: visible to a player.** Spud streams spaces and renders destinations through door openings; docs defer dynamic bodies/NPCs crossing portals, navmesh links, door sound propagation, and some door animations. Evidence: [docs/ARCHITECTURE.md:93-105](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/ARCHITECTURE.md#L93-L105).
4. **Jolt replaces Havok. Severity: affects gameplay correctness.** Vision explicitly rejects bit-exact physics and permits fixing physics quirks. Evidence: [docs/VISION.md:8-20](https://github.com/chasmlol/spud/blob/8c9904207a5c573a0193fb903fb5c433f127f102/docs/VISION.md#L8-L20).
5. **No whole-frame temporal AA or upscaling. Severity: visible to a player.** README and render policy ban these techniques; water and other effects may use local temporal state. ## Claims versus code

- **No TAA:** supported by a static audit that scans render source and shaders for banned identifiers, and visible shaders show history isolated to water. This proves policy/check presence, not that the audit passed on this checkout because no audit was run.
- **Native formats at runtime:** architecture describes importer as the sole legacy-format layer. DDS header docs explicitly call DDS a generic format kept as-is, and README says WAV files remain WAV. So “original game formats are read only by importer” needs its stated generic-format exception.
- **Bring your own game:** README, architecture, and launch flow align: local cache defaults under LocalAppData, and launch imports when no Tamriel world asset exists. Repo claims no game content is shipped.
- **Headless parity:** automation docs say headless uses the same render passes and requested size, but the performance report warns headless presentation may use a compositor blit and differs from windowed measurement. Visual output is not proof of display-pacing parity.
- **Image determinism:** audit compares fresh process with camera travel and later frames, allowing up to 1% differing pixels. This is narrower than bit-for-bit determinism stated in rendering docs.
- **Test suite claim:** the automation doc contains malformed text around “UI test suite”; docs/UI.md separately says skytool can run movie files headlessly and report script errors. The suite's exact size and runner were not established.
- **Build support:** README explicitly says Windows, presets use x64-windows, and Linux is roadmap-later. No CI workflow was found in the checkout.
- **Docs quality:** several documentation strings are incomplete or malformed, including the LOD paragraph, architecture's anim row, and the UI suite invocation. Treat unclear claims as unverified until source or a corrected doc settles them.
- **Features in code with sparse meta documentation:** gate contamination and disk thresholds, clean-run retries, shared/exclusive scheduling, and detailed performance statistics are specified mostly in tool code rather than README-level docs.

## Process lessons for Mudcrab

- Copy the evidence discipline: define fidelity tiers and require comparison with the original game before calling behavior verified.
- Copy the shared command language and headless control approach. The same scripted actions can support acceptance checks, captures, and agent investigation.
- Copy explicit machine-specific baselines, robust repeated-run summaries, and contamination detection for performance work.
- Copy reversible changes and evidence-rich performance notes that separate measured effects, side effects, and untested cases.
- Copy contributor rules that prohibit committing game data and separate importer knowledge from runtime format handling.
- Avoid a platform gate tied to one OS if Mudcrab needs cross-platform builds. Keep platform scope and CI status visible.
- Avoid using documentation breadth as a proxy for working feature coverage. Track executable checks, scenarios, and unverified claims by feature.
- Avoid treating a small pose set or a fixed UI suite as broad visual parity. Label coverage boundaries and keep original-game comparisons distinct from internal repeatability.
