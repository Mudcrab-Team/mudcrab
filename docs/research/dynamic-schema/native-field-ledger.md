# P0 field and native-loader evidence ledger

Status: bounded research slice, 2026-10-04. This ledger cross-checks selected `REFR`, `CELL`, and `STAT` fields against pinned source declarations, Mudcrab's converter, and static code from Skyrim AE `1.7.104.0`. A static load path shows what the executable reads or dispatches; it does not establish runtime effects. This is not field-complete for any record type and makes no P0 acceptance claim.

## Current converter, SQL, identity, and cache behavior

The public `EsmParser::convert_plugins` path reads the caller-supplied plugin order, merges parsed records, creates the SQLite schema, stores each plugin's SHA-256, and exports the merged records. The repository does not have an accepted active load order yet, so this describes current source behavior rather than the exact winner set for the installed game.

| Boundary | Current behavior in base and `origin/main` | Source anchors |
| --- | --- | --- |
| Plugin order and slots | `LoadOrder::read` rejects duplicate case-insensitive names and dependents that precede a listed master. It assigns full slots in supplied order and light slots to `.esl` or ESL-flagged plugins. `identity` maps a resolved ID back to the owner plugin and local ID. | `crates/converter/src/esm/load_order.rs:100-167` |
| FormID remap and winners | Ordinary IDs map the owner into the full load-order slot. Light IDs use `0xFE`, a 12-bit light slot, and a 12-bit local ID. Selected subrecord links plus record cell/worldspace links are remapped. Later non-deleted records replace earlier records; a deleted winner removes that form. `GMST` is special: case-insensitive `EDID` keeps the first canonical ID while later values replace it, and aliases let header-only deletions target the same ID. | `crates/converter/src/esm/mod.rs:60-156,180-233,316-425` |
| SQLite projection | `records` is keyed by resolved FormID and stores record type, owner priority, cell/worldspace links, and serialized parsed subrecords. `formid_map` stores resolved ID to owner plugin/local ID. `references.data`, `cells.data`, and `records.data` carry tag/payload projections. | Typed fields | `CELL.flags` comes from the record header; `CELL/DATA` remains in its subrecord blob. `CELL` types only XCLC X/Y and EDID in this helper. `REFR` types NAME, DATA, XSCL, and XRDS; it does not type header flags or XESP/XPRM/XLIG/XEMI. `STAT` types EDID, model path, and record-header flags; its other listed fields remain in raw subrecord data. | `crates/converter/src/esm/exporter.rs:259-288,329-382,635-689`; `crates/converter/src/esm/extractors.rs:72-110` |

That reader sends the 32-bit parent ID to RVA `0x165660`, which removes the extra-parent entry for zero or creates/updates it for nonzero, then writes the following flag byte when an extra-parent entry exists (`shard-0018.c:42078-42090`; `shard-0011.c:20925-20943,27595-27640`). | This establishes native parse storage and zero-link handling. The native constructors above map 3/4 to plane/line objects. The unnamed Mutagen value and terminology difference remain open; these names do not establish runtime behavior.
